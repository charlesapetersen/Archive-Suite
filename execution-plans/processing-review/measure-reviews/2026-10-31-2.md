## 2. Findings

### P2-1 · the kit checker can pass without its required comparison — high; classes 2, 4 and 5

Baseline 9d8ab697, `ArchiveProcessor/scripts/segbench/institutional-compute/train_seg.py`:

- `cmd_check` promises an anchor score, held-out score and a paired interval against the shipped model whose
  lower end exceeds -3 points. But it checks the lower end only **if** `difference_interval` exists. A
  non-shipped candidate with no shipped run, or no common held-out answer, passes with no such interval.
- `heldout_groups` skips every expected gap absent from the candidate's votes. `gap_score` pairs only available
  reference votes. Thus a run answering an easy subset can pass with a perfect score while its missing gaps
  disappear; `failed_windows` is reported but does not supply expected gap coverage. A failed overlapping window
  need not mean a missing gap, so rejecting every window failure is not the remedy.
- Functional reproduction: import the module, replace only `run_votes` with synthetic dictionaries, and call
  `cmd_check` with a complete three-page anchor (`New, Cont, New`) and two held-out labels in two folders.
  Candidate votes cover only the first held-out gap. These were the observed results:

| synthetic case | expected held-out gaps | candidate scored | paired gaps | paired interval | exit / passed |
|---|---:|---:|---:|---|---|
| no shipped run | 2 | 1 | absent | absent | 0 / true |
| shipped votes only on the other held-out gap | 2 | 1 | absent | absent | 0 / true |
| shipped votes on both held-out gaps | 2 | 1 | 1 | [0, 0] | 0 / true |

**Fix:** `W46.kit-gate-coverage`. Require the reference and paired evidence for a non-shipped candidate;
enumerate expected, answered and paired held-out support, distinguish missing evidence from success, and prevent
selective missing answers from satisfying the gate. Keep strict coverage/failure reporting beside answered-only
diagnostics, use the same known-gap support for the comparison, and add synthetic regressions for these three
cases plus a complete valid comparison. Preserve Phase 4's choice of the proposed -3-point threshold. This
finding concerns the training checker; the app's deliberately narrower manifest admission rule is a separate
rule and is not silently changed here.

### P2-2 · unsure gaps become artificial agreements, not excluded observations — medium; classes 1 and 4

Baseline 9d8ab697, `scripts/segbench/score.py`: `Truth`, `forgive`, `score_labels`.
`score_labels` first gives each unsure gap the prediction's own call, then its boundary loop still increments
`c.gaps`, `truth_bounds` and `tp`. The unknown gap cannot become a false split or merge, but it contributes an
artificial agreement to accuracy, F1 and kappa. The full gap denominator is the same across routes; truth-boundary
counts and segment truth become route-dependent.

Synthetic reproduction: `Truth(['New', 'Cont', 'New'], [1])` has two document gaps, one known. Against
`['New', 'New', 'New']`, `score_labels` returns gaps=2, truth_bounds=tp=2, docs=3. Against
`['New', 'Cont', 'New']`, it returns gaps=2, truth_bounds=tp=1, docs=2. A genuinely masked boundary score would have
one scored gap in both cases. These outputs were measured with the current scorer, without corpus inputs.

`seg-truth-rescore.md` does disclose that pages exact is conditional on each route's reading of unsure gaps, and
correctly treats CREST's small spread as a tie. That disclosure stands. It does not make the boundary metrics
masked, nor justify comparing route-dependent segment truth as one fixed truth.

**Fix:** `W46.seg-unsure-mask`. Exclude unsure gaps from boundary counts, calibration/risk and paired known-gap
comparisons; retain the unscored count. For segment metrics, state the conditional estimand and use common
resolvable support or sensitivity bounds when comparing routes. Preserve fully ruled boxes byte-for-byte in the
metrics; test both kinds of unsure prediction, adjacent unsure gaps and no-unsure cases. The locked-box scoring
must inherit this before it ranks routes. This is a scorer correction, not a request for another owner sheet.

### P2-4 · shared errors do not establish a training ceiling, and label noise need not cancel — medium; class 5

Baseline 9d8ab697, `kit_gate.py:render`, `seg-kit-gate.md`:

- The teacher split says shared wrong gaps “cannot be trained away with this teacher” and says the public split
  measures how far a second-family teacher could help. This measures co-errors of frozen runs, not the effect of
  changing training. Students already get some teacher-wrong gaps right. Generalisation, data coverage and shared
  conventions can produce overlap without proving inherited causation or a hard ceiling.
- The sample-size reading says tag noise “shifts both models' scores alike in a paired difference”. It cancels
  where the models agree. At a discordant binary gap, reversing the truth reverses their signed accuracy
  difference. The 5.3% label-error estimate does not locate those errors on the models' agreements or disputes,
  so cancellation is not established. This is reasoning about the estimator, not a new measured noise rate.

**Fix:** carry both conditions in `W46.seg-report-refresh`: describe overlap rather than inherited causation,
do not forecast a second teacher's gain, and qualify paired tag scores with truth-error sensitivity on discordant
gaps. Preserve the measured label-error intervals and the sampling-only nature of the bootstrap. No new paid arm
or training run is justified by the overlap alone.
