# 13. Stage rules and the rule table (Phase 4)

Owner, 2026-11-06: Phase 4's output is what the settings layer loads (`00-plan.md` §"Phase 4"; the layer is
`12-settings-design.md`). This folder holds one rule note per stage and, here, the schema of the table those notes fill.
The notes are drafted from the strand notes, the result notes, `11-measurement-audit.md` and every pass under
`measure-reviews/`, then checked against the passes, then walked with the owner. The table itself,
`ArchiveProcessor/segbench-results/settings-routes.json`, is generated by `ArchiveProcessor/scripts/segbench/settings_routes.py`
(W46.settings-routes-table, 2026-11-11): the reading stage's single routes from the bench's result files, every other row
and stage object from the JSON in each note's section 4, so a row is changed in its note and the table rebuilt. The drift
test, `ArchiveProcessor/scripts/test-settings-routes.sh`, fails when the table is not what its inputs give or a figure is
not found in the file its source names.

## The note format (every stage, in this order)

1. **Stage and question.** Two lines: what the stage does to a page or document, and what the user is choosing, or
   why there is nothing to choose.
2. **Is there a choice?** Yes: the routes below and the stage rule. No: the rule, the measured reason, and the switch
   if the owner ruled one (its id, label and default).
3. **The rule for the settings layer.** The text the sheet shows, then: the comparison metric and its tie rule, the kind
   rules (a kind that gets a different route or none), the fallback when the chosen route fails on a page, and when the
   stage must not run at all. Written so a Swift solver could apply it from the table alone.
4. **Table rows.** One JSON object per route in the schema below, or "none". Every figure copied from a named file.
5. **Caveats carried.** Each finding of `11-measurement-audit.md` and each measure-review pass that bears on this stage,
   by id (SEG-8, P9-1, R-3 ...), with how the rule respects it: a figure replaced, a condition on a row, a caveat string.
6. **What would change the rule.** The measurable trigger: a model that clears a named figure on a named set, a price
   below a named level, a feature the app gains.
7. **Owner calls.** Only what the figures do not settle. Each: the question, the options, the evidence with its figures
   and files, a recommendation where there is one. The queued calls named in the brief must each appear here or be
   shown settled.
8. **Items to file.** Each with a name, what done looks like, a size, what it waits on; including every figure the table
   needs and the bench has not produced (a gap, `12-settings-design.md` §3.9).
9. **Profile test expectations.** For each of the plan's five profiles (a laptop only, open weights, at 16, 32 and 64 GB;
   cheap API; premium APIs or plans; a cluster; any of these plus a coding agent) and each document kind this stage
   distinguishes, the pick the solver must make from the rows, with the row and figure that decide it. These become the
   solver's test cases.

Figures carry [M] measured, [I] inferred, [?] unverified. Plain prose. No figure is recomputed from other figures; a
figure a later pass corrected is given in its corrected form with the pass id. Length: about 120 lines for a no-choice
stage, about 250 for a choice stage.

## The table schema (`settings-routes.json`)

Top level: `version`, `built` (date), `item`, `method` (the generator), `noise` (per stage: `metric`, `tie` with its
unit, `source`), `stages` (list). A stage: `id`, `name`, `unit` (`pages` or `documents`), `choice` (bool), `metric`
(`id`, `label`, `higher_is_better`), `kinds` (the kind ids the stage scores apart), `rules` (list of `{id, text, source,
switch}` where `source` is the string form "file.md §section" and `switch` is null or `{id, label, default}`), `fallback` (the route id or built-in behaviour when every
route fails), `routes` (list; empty for a no-choice stage).

A route row:

```
{
 "id": "gemini3.8-flash",            the bench's route id; stable across rebuilds
 "name": "Gemini 3.8 Flash",
 "family": "mac" | "cloud" | "plan" | "cluster" | "manual" | "kit",
 "app_route": "gemini|gemini-3.8-flash" | null,     the Processor's provider|model id when the app offers it
 "status": "shipped" | "measured" | "after-training",
 "needs": {"key": ["gemini","openrouter"], "plan": [], "cluster": false, "mac_gb": 16, "gpus": 1},
 "figures": {                       per kind the stage scores apart, and per public stratum where run
   "typewritten": {"value": 96.0, "n": 50, "truth": "owner-96", "source": {"file": "...", "route": "...", "attribute": "...", "value": "..."}},
   ...
 },
 "cost": {"usd_1000_list": 0.9, "usd_1000_batch": 0.45, "price_read": "2026-10-15", "source": {...}},
 "time": {"per_unit_s": 6.0, "measured": false, "measured_on": "gateway OCR calls, date-image.md" , "source": {...}},
 "memory": {"peak_gb": 7.6, "measured_on": "M3 Pro 18 GB", "source": {...}},
 "caveats": ["2 of 96 refused; price doubles 1 Jan 2027", ...],      each traceable to a file
 "kind_rules": ["newspapers: regions first (layout stage)"],
 "fallback": "apple-vision" | "text-page" | null,
 "conditions": ["after the kit's gate passes on held-out gaps (seg-kit-gate.md)"]    for after-training rows
}
```

Fields the notes added, as built (W46.settings-routes-table):

- Stage: `note` (the stage note), `metric.figure` (the figure key the metric is read from; `<kind>` for the kind being
  ranked), `kind_strata` (reading: the public strata each kind is scored on), `routes_role`
  where a no-choice stage still has rows (rotation's, picked by rule; the kind classifier's; the kit's after-training
  rows). Top level: `schema`, and `noise` holds one entry for every stage.
- `needs`, one shape on every row. Access is any one of: a key in `key`, every plan in `plan`, or `cluster` (`gpus` a
  job); a row with none of the three runs on the Mac alone. `mac` true means the route runs on this Mac, so its memory
  must fit (`memory.peak_gb` plus the solver's headroom; `mac_gb` a note's stated floor, else null); `built_in`. Key names: `gemini`, `openrouter`, `openai`, `mistral`, `anthropic`,
  `gateway` (the Stanford gateway).
- Row: `step` (dating's pipeline steps), `stages` and `trigger` (cascades), `delta` (placement, a difference with no
  level). Figure keys are kinds, public strata, or `<kind>.<attribute>`; a figure may carry `strict`, `failures`,
  `metric`, `interval`, `derived` (how a stated count becomes the value), and string values where the file gives a
  pair. Reading rows give `typewritten`, `printed`, `handwritten` as strict NES with `answered` and `n` beside (the
  bench has no answered NES per kind), `overall` answered with `strict` beside. `memory.whole_process_gb` with
  `memory.whole_process_source`; `time.per_unit_s` is always per the stage's unit, a window's seconds kept as
  `time.per_window_s` (segmentation: a seven-page window every 3 pages); `time.per_unit_ms`, `time.per_1000_s`,
  `time.pages_per_hour_per_gpu_set` for cluster rows.
- An unmeasured estimate (a figure only the 2026-11-04 prototype held) has `source: null`, `measured: false` and an
  `estimate` string saying where it came from.

`source` has the shape the app's `ocr-page-guidance.json` already uses (`file`, `route`, `attribute`, `value`), so one
drift test can check every figure against the file it names. Memory needs are the measured peak; the solver adds its own
headroom (the prototype used 5 GB). Cloud seconds are `measured: false` until the bench tabulates them.
