## Session 1 (2026-11-13)

**Method of the move:** a filtered subtree merge (first checkpoint commit). A clone of `~/Claude/vision-ocr` at its
1.16.0 release plus two later doc commits, run through `git filter-repo` keeping only `Sources/ Helper/ Tests/
Tools/ Resources/ testdocs/ run_tests.sh build.sh`, moved under `packages/VisionOCRKit/`; 300 of 633 commits. gitleaks
clean; both repositories are public.

**Layout:**
- `Sources/VisionOCRKit/` — the library: every engine file. `DownloadRunner` moved here out of `SettingsView.swift`,
  because `ModelDownloads` names it. Resources `read-model.py` and `mac-ocr-LICENSE` are package resources
  (`Recogniser.ModelRuntime.script()` falls back to `Bundle.module` under `SWIFT_PACKAGE`).
- `Helper/` — the `visionocr-recognise` executable product (`import VisionOCRKit`; the few names it uses are public).
- `App/` — Vision OCR's screens (`App.swift`, `ContentView.swift`, `SettingsView.swift`, `Info.plist`), in no
  package target. `build.sh` and `run_tests.sh` still build the app and the suite with swiftc from the new paths:
  that is the reference lane.
- Minimum macOS 14 everywhere (Package.swift, every `-target …-apple-macos14.0`, `LSMinimumSystemVersion`).

**Baseline on this Mac (macOS 27.2, Swift 6.4.2), unchanged imported files, `run_tests.sh`:** 2123/2137 passed.
The 14 failures are all outline fixtures ("the fixture really has an outline" … C35 outline rows): the fixture
builds no outline on this macOS, so they are environmental and pre-date the move. Parity target: 2137 checks,
the same 14 failing.

**Measured:** `swift build -c release --arch arm64 --arch x86_64` builds; the helper is `x86_64 arm64`, answers
`--version`, links no SwiftUI; the bundle carries both resources. Warnings: the two Vision OCR's swiftc build
already prints (Model.swift:1128, Recogniser.swift:531), none new.

**The checks as a package target (done, checkpoint 1b):** `visionocr-checks` executable target (Tests/main.swift
with `@testable import VisionOCRKit` under `#if SWIFT_PACKAGE`) and the `VisionOCRKitTests` test target
(`PackageTests/`), which builds the plate fixtures and runs the checks from the package root with the package's
helper. `swift test -c release -Xswiftc -enable-testing`: **2123/2137, the same 14 outline failures as the
baseline**, 457 s. Test edits: the Prefs.store scan reads `Sources/VisionOCRKit` and `App`;
`SettingsView.languageLabel` moved to `Recogniser.languageLabel` (the checks link no screens).

**ux-regression through package products (wired, checkpoint 2; not yet run):** `visionocr-gate` executable target
(`Tools/gate/main.swift` is a symlink to `Tools/score-gate.swift`, which gained the guarded `@testable import`);
`Tools/ux-regression.sh` now builds the gate and the helper with `swift build -c release -Xswiftc -enable-testing`
and copies them with the resource bundle into its run folder. `ops/ux-regression/{set,baseline}.tsv` copied from
the Vision OCR repository (baseline last changed in its 4b6567b, 2026-10-14, before the 1.16.0 release).
**It cannot run yet:** it needs the 1.2 GB corpus `testdocs/` (book/, …), which moved to the owner's OneDrive backup

are present; the accurate rows' models are in `~/Library/Application Support/Vision OCR` (pass

**The app rebuilt against the package — decided:** `build.sh` compiles App/ with the package's own sources as one
module, and both suite lanes give the same count. That is the proof the criterion asks for (nothing lost in the
move). Making App/ `import VisionOCRKit` would need a public API for everything the screens touch, which is Stage
2's `PageReader` design, for an app that Stage 7 retires; not done here.
