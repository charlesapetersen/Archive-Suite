## Necessity and size review (2026-10-29)

1. **The question, and what it could change.** Should every segmentation window carry a COLLECTION FACTS
   block (H-corpus test 5, gap audit item 33)? If the block helps on material the students never saw and
   costs nothing on the owner's boxes, the app's window prompt (`WindowPrompts.swift`, all profiles) gains
   one, filled from what the app already holds: the confirmed box and folder label photos, the years in
   the OCR, and the lengths of the owner's earlier boxes. If it does nothing, or hurts, the prompt stays
   as it is and `W46.seg-context-paid` (Gemini, the app's default segmenter, about $1.40 in batch) can be
   dropped or kept small. The 2B is the laptop route, so a Lincoln gain for it would also matter there.
2. **Why the results in hand do not settle it.** Nothing measures collection facts anywhere (H §6.1,
   question 5). The nearest result, the stated letter cue (`seg-lincoln-cloud.md`, c2 against c1), is a
   different text and was run only on Claude: no change in pages exact, fewer checks on Lincoln. The
   students fail Lincoln by over-splitting (the 2B 44 false splits and 2 false merges, the teacher 40 and
   0), which is exactly what a document-length prior addresses, and the CHR result predicts the
   effect is under a point on the owner's boxes, so it has to be measured on both kinds of box.
3. **Size.** Four jobs: a CPU stage, the teacher on one GPU, a CPU merge, the student on one GPU.
   - 255 windows (CREST 44, Lincoln 88, Stanton 84, RG165 39) x 2 arms = 510 requests per model.
   - Timing from FarmShare on these very boxes and models (`FarmShare-20261018/results/seg/public-*`
     summaries, concurrency 16): the teacher read Lincoln's 88 windows in 504 s and CREST's 44 in 294 s,
     about 5.7 s a window, so 510 take about 50 minutes; the 2B read 88 in 41 s, so 510 take about 4
     minutes. With vLLM start-up (up to 30 minutes allowed), about 1.3 GPU-hours in all.
   - Ceiling 3.5 GPU-hours: the teacher job's 2.5-hour limit and the student's 1 hour.
   - Each GPU job is its own pilot: 4 windows first, and the full run only if at least 3 parse.
   - Smaller would not do. Lincoln alone answers the half the block is meant for but not whether it
     costs the owner's boxes, which is the condition for shipping it. CREST is 44 windows (about 4
     minutes of teacher time), where the students already do well: a ceiling check that the block does
     not distract a model that is right.
4. **Verdict: useful now.** It decides a prompt default for every profile and gates the Gemini arm, at
   about 1.3 GPU-hours.

Not in this pack, filed as `W46.seg-context-more` behind `W46.nice-to-have`:
- **The 2B LoRA with the block in its training rows.** It needs a block for each of the 5,885 training
  windows' folders (corpus boxes with no catalogue line), the training environment Sherlock does not
  have, and a full retrain. It is only worth doing if the prompt arm shows the block helps.
- **The tagging prompt** (`TagGenerator.swift`, `date_tagging.py`). The item's two models are
  segmenters, not the app's tagger, and the era fact comes from the same OCR the tagger reads, so the
  block's dating test belongs with the tagger's own route.

## What the pack holds

`seg_context.py pack` (rebuilt after the review, at this checkpoint) wrote
`/Users/cp1/.local/state/archive-autonomous/artifacts/seg-context-20261029/` (145 MB, 855 frozen files):
`freeze.json` (each box's block, its facts and every file's SHA-256), `images/` (the 752 pages at
1024 px, as every window request carries them), `teacher/` and `student/` (510 requests each, base and
block interleaved per window), `support/segbench/` (the bench modules, `cluster_seg.py`, `train_seg.py`)
and `support/job/` (the four scripts, `sh.env`, `bin/`).

- **The base arm is the scored request, byte for byte.** `pack` refuses unless every base request's cache
  key equals the key of the earlier FarmShare row (public boxes: the committed packs' keys; owner boxes:
  the response cache), and for the public boxes every image's JPEG bytes equal those the scored packs sent.
  So the block is the only difference between the arms.
- **The block** sits just above the prompt's OCR heading ("THE OCR TEXT OF EACH PAGE"), so it is not read
  as page text, and states, for the whole box: the catalogue
  line and item count (CREST, Lincoln) or what the box and folder label photos' OCR reads (owner boxes,
  up to 8 labels, 160 characters each); the span of years in the box's OCR; how many pages carry little
  OCR text; and a length prior (pages per catalogue item, or the owner's three development boxes'
  document lengths). Nothing comes from the box's own boundaries. `seg_context.py facts` prints them.
- **Caveats to read the results by.** CREST's era reads 1978 to 2008, the 2000s commonest, because the
  release stamps ("Approved For Release 2008/…") outnumber the documents' own dates. RG165's "folder
  label" photos are document pages with a folder card, so their OCR is mostly document text. Both are
  what an app would compute, so they stay as they are. The kind mix is a text-density stand-in: the
  Vision kind sorter has no per-box output for these boxes.
- **The test boxes.** Stanton and RG165 are the locked test boxes. Nothing is fitted on them: one block
  per box, fixed before any answer, and the same windows as the frozen teacher's one test-box run.

## Read the results by these (the adversarial review, 2026-10-29)

- **The public block is stronger than the owner one.** CREST's and Lincoln's truth was built from the same
  catalogue items, so "the catalogue lists N items" is a lower bound on the truth's documents (22 against 31,
  72 against 81). A catalogued collection really gives an app that, so it is fair, but report the public and
  owner gains apart and never carry the public gain over to the owner's material.
- **Weights at "main", not FarmShare's revision.** FarmShare recorded no snapshot hash, so the stage job fetches
  `main` and the runtime records (`runtime/*.json`, the model path's last part) say which weights were read. If
  Qwen has updated either repo since 2026-10-18, the base arm against the committed FarmShare rows measures that
  too; the base-against-block comparison, read in the same job, does not depend on it. So does the GPU: Sherlock's
  48 GB class includes Ampere cards, and the runtime record names the card.
- **Photos when comparing to the committed rows.** `seg_context.py score` uses truth photos for the owner boxes
  and the model's own for the public ones, as `public_segmentation.py score` and `report_five` do. When the
  write-up sets the base arm beside a committed row, score both with the same photo setting.

## Owner-started session: stage and submit

1. Read Sherlock's current `/etc/agents/AGENTS.md` and topic rules, and this review.
2. Check the adapter path: `ls $GROUP_HOME/$USER/archive-suite/FarmShare-scratch-20261022/fs-ocr/train/seg-2b/`
   should show `adapter/` (with `adapter_config.json`) and `train.json`. It is the adapter behind
   `fs-seg-2b` (`institutional-compute/train.sbatch`, `$IC_ROOT/train/seg-2b/adapter`); the engine could not
   look. If it lives elsewhere, export `SEG_CONTEXT_ADAPTER=<that adapter folder>` before submitting.
   The pack manifest lists both paths under `requires`, so `batch.sh check` reports them too.
3. Copy the prepared folder to `$GROUP_HOME/$USER/archive-suite/seg-context-20261029/` with its structure
   (the batch's `batch_mac.py send` does this; manifest `packs/W46.seg-context.json`).
4. Submit:

   ```bash
   bash "$GROUP_HOME/$USER/archive-suite/seg-context-20261029/support/job/submit.sh" \
     "$GROUP_HOME/$USER/archive-suite/seg-context-20261029"
   ```

   It reserves `$SCRATCH/fs-ocr/seg-context-20261029/jobs.tsv` before the first `sbatch` and refuses a
   second invocation; if a submission fails, read that file and `squeue` before anything else.
5. The stage job downloads `Qwen/Qwen3.5-27B-FP8` (about 31 GB) and `Qwen/Qwen3.5-2B` (about 5 GB) into
   `$SCRATCH/fs-ocr/hf` if they are not there. The merge job builds a peft overlay venv in
   `$GROUP_HOME/$USER/envs/peft-overlay`, every package the image has held to the image's version.
6. Collect `$GROUP_HOME/$USER/archive-suite/sherlock-results/seg-context-20261029/` (runs/teacher,
   runs/student, their pilots, runtime records, vLLM logs) into the Mac artifact as `results/`, then
   `plan-edit.sh … release W46.seg-context 'results in <path>'`.
