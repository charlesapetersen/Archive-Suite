# W49.storage-finder — session notes

Owner answers (W49.storage-finder-owner-ok, walkthrough 2026-11-27): **1c** Finder tag mirroring off everywhere by
default; **2b** adoption leaves Finder tags behind, and when mirroring is explicitly on, a tag edited in Finder is
offered as Import or Re-publish, never taken silently; **3b** an undoable "Remove suite tags" when mirroring is turned
off, removing only tags the suite recorded writing; **4 no** — no separate Finder-mirroring setting for Notes'
`.archivenotes` packages (Notes' own note-tag projector is left as it is).

## Checkpoint 1 — 2026-11-27 (Opus 5.5)

Done: the Processor no longer mirrors by default.
- ArchiveCore `CataloguePairFiler.filePair(carriesFinderTags:)` (default false): the prepared-PDF copy skips
  `com.apple.metadata:_kMDItemUserTags` and `com.apple.FinderInfo` through a `fcopyfile` status callback; other
  attributes still travel. Test: `preparedFilingCarriesFinderTagsOnlyWhenMirroring` (both ways).
- Processor general setting **Mirror archive fields to Finder tags** (`mirrorFinderTags`, Settings ▸ Output, off),
  frozen into `ResolvedRunConfig.mirrorFinderTags` and each `ProcessorCatalogueFiling` request (`carriesFinderTags`),
  so a resumed filing keeps the run's answer. Process Files, Live Capture and Adoption (always false) pass it.
- `scripts/test-finder-mirror.sh` ($0, stand-in gateway): off → filed PDFs carry no tags or label and their
  companions hold Unread; on → Unread and the generated tags as before; source photos keep their own tags.
- Exported original images (Process Files and Live Capture) are copied through the same filter
  (`CataloguePairFiler.copyFile`), and a resumed paid batch keeps the run's frozen answer.
- Tier-2 review (Opus subagent): no blocker; its two medium gaps (exports, paid-batch resume) and the copy
  callback's error handling (`COPYFILE_ERR` now stops the copy) are fixed in this checkpoint.
- Harnesses that assert filed tags (tier-2, Review Dialogs / Live Capture / Bulk OCR journeys, e2e-phone-mac,
  e2e-ios-ui, live-openrouter, repro-suspects-filing) set the Debug-only `ARCHIVEPROC_TEST_MIRROR_FINDER_TAGS=1`.

## Checkpoint 2 — 2026-11-27 (Opus 5.5)

Reader discovery in tags mode: `CorpusScanResult.catalogueCompanionsSeen` (the walk and the indexed revalidation both
count `CatalogueRecord.isCompanionFilename`), published as `ArchiveLibrary.catalogueCompanionsSeen` when a pass
completes. An empty tags-mode list in a folder with companions says how many PDFs keep catalogue records and offers
"Use Catalogue Companions for This Folder" (`ar.empty.catalogueRecords`, `ar.empty.useCatalogue`). Chosen over
admitting companion-bearing PDFs into the tags-mode list, which would have let a tags-mode edit write Finder tags
onto a catalogue-owned PDF (a second authority, against 2b). A mixed folder (tagged legacy PDFs plus untagged output)
gets no notice yet; adoption is the route for those. Tests: `testScanCountsCatalogueCompanions`,
`testUntaggedCatalogueOutputOffersCatalogueCompanions` (VM).

## Remaining sub-steps

1. (Done in checkpoint 2, above.) Possibly a notice for a mixed folder, if the pilot shows it is needed.
2. **Reader projection when mirroring is on.** A per-archive Reader preference (beside the catalogue-mode key), off
   by default. When on, a catalogue edit projects the facts' tag vocabulary through `CoordinatedTagWriter` and
   records exactly what the suite wrote (an ownership ledger per occurrence).
3. **Divergence (2b).** With mirroring on, detect a mirrored tag changed in Finder and offer Import (take the Finder
   value into the record as a user edit) or Re-publish (write the record's value back); never adopt it silently.
4. **Remove suite tags (3b).** On turning mirroring off, offer an undoable removal of only ledger-owned tags; hand-made
   tags and tags the suite cannot prove it wrote stay.
5. (Done in checkpoint 3.) Improve OCR's flagged-files finder reads a PDF's companion when it has one: the record's
   OCR Poor decides, a stale tag or an unreadable record leaves it unlisted (`test-reocr-job.sh` section 16).
   `ReOCRJob.isFlagged` (clear and reflag) still reads tags only; it touches only tags already present, so it never
   tags a clean PDF.
