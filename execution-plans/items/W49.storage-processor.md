# W49.storage-processor

The shared XMP identity codec reads the exact open PDF descriptor. Scratch filing fixtures use
that codec for both initial publication and recovery. Both PDF generators and the merge writer
accept an explicit catalogue identity. The producer still needs to supply it on the filing paths.
Keep existing header rewrites on working PDFs or replace them with catalogue field updates before
publication.

- Build initial records from typed Processor results before formatting the PDF provenance.
  Give each source page and physical page its own ID. For split segments, put the fields in one
  owner's companion and reference it from the other members.
- In Live Capture, persist the operation UUID, final path, root instance and exact initial record
  before filing. Keep each staged PDF and the raw photos through pair verification. Retry the
  recorded destination even when its PDF contributes to the current collection number. Gate the
  existing filed-group ledger and retirement on every pair and the existing image checks.
- In Process Files, keep working PDFs separate from the final pair through review and
  organization. Cover fresh input, cached and paid batch resume, retry, split and merge, and
  the separate multi-page PDF journal. Recognize only verified pairs when skipping or resuming.
  For pre-OCRed input, preserve the source bytes and use the supported exact association for a
  pre-app PDF. Keep inputs and components on any unresolved filing outcome.
- Exercise the normal paths with scratch fixtures, including a destination collision, a crash
  after publishing only the PDF, and a second retry. Optional segment JSON stays an export.
  Improve OCR and restore remain the separate rerun item.
