# W40.suite-app-icons — progress notes

**2026-11-06, session 1 (checkpoint).** Before this item Notes shipped a byte-identical copy of Reader's icon
(the same md5 at every size). That is the confusion the owner reported.

- `release/make-app-icons.swift` draws three candidate sets with offscreen CoreGraphics (no window):
  `swift release/make-app-icons.swift sheet <out.png>` draws the candidate sheet, and
  `swift release/make-app-icons.swift install <A|B|C>` (run from the repo root) writes one set into all three
  macOS `AppIcon.appiconset`s at every size.
- The sheet is `release/app-icon-candidates.png`. It shows each app at 256 px, and the three side by side at 64,
  32 and 16 px on a light strip and a dark strip.
  - **A**: today's folder of papers stays as the family look, with a glyph per app (Processor a tag, Reader
    glasses, Notes a pencil) and a colour per app (blue, amber, green).
  - **B**: one object per app (Processor a scanned page in a viewfinder, Reader an open book with a ribbon,
    Notes a page with a quotation mark and a pencil writing). Its shapes differ the most at Dock size.
  - **C**: a cream page with the app's initial (P, R, N). The plainest of the three.
- **Set B is built into all three apps now** as the recommendation, so Notes and Reader no longer look alike.
  actool compiles all three catalogues with no warnings. The Notes Debug build contains the new `AppIcon.icns`
  (checked by extracting it).
- Waiting on `W40.suite-app-icons-owner-ok`: the owner picks A, B or C, or asks for changes. To finish: if the
  pick is not B, run `install <set>` (or edit that set's drawing function and re-run `sheet` and `install`).
  Then build and move the entry to DONE. The iOS capture companion's icon is outside this item.
