## Shared causes, measured in the macOS 27.2 guest

1. **2× display — FIXED (checkpoint 1).** The guest boots at 1920×1200 points on 3840×2400 pixels;
   `vm-set-display.swift` now asks for the low-resolution duplicate modes and switches to the 1× 1920×1200
   mode. The switch does NOT persist across a boot (`.permanently` notwithstanding), so every lane run
   switches it; the runner log says `1920×1200@2x → 1920×1200`. Screenshots are 1920×1200 again.
   Reader snapshot reference re-recorded at 1× (300×180) in checkpoint 3; SnapshotTests passes.
2. **Pointer drags — FIXED (checkpoint 2).** `press(forDuration:thenDragTo:)` delivers no mouse events on
   macOS 27; `click(forDuration:thenDragTo:)` does. All 19 UI-test call sites changed. A click drag loses
   ~3 pt to the drag threshold; `LayoutGuard.dragCorner` corrects. Processor LayoutGuardUITests 3/3 pass.
3. **Window sizing** — was the drag problem (the layout guard's resize is a corner drag). Processor's
   "neither shrink nor grow" is gone. Notes "reach down to the Dock" uses `dragCorner` too: not yet re-run.
4. **TransientCheck "never reported idle" / "no watched section changed" — FIXED (checkpoint 4).** Not the
   observer's order (all orders up to 2_000_000_000 fire every pass in the guest). The guest log showed
   `NSInvalidArgumentException: -[NSConcreteAttributedString _fastCStringContents:]` from the app on every
   run: SwiftUI answers `accessibilityTitle`/`accessibilityLabel` with an NSAttributedString on macOS 27,
   the walk took it as String, and the exception out of the run-loop observer left it marked firing, so it
   never sampled again. The walk now reads both as objects. Reader TransientStateUITests after the fix:
   the recorder samples (210 samples, walk ≤ 86 ms); commonTransitions now stops at "Not hittable"
   `ar.sidebar.folder` at x −105 (the Reader's sidebar overflow, also in its LayoutGuard: per-app), and the
   planted-flicker test says "next file, planted flicker: no watched section changed" — check next whether
   that is the Reader's next-file action at this window size or the walk (rows) before handing it on.
   Debugging recipe that found it: `log show --last 30m --style compact --predicate 'process ==
   "ArchiveReader" AND eventMessage CONTAINS[c] "exception"'` in the guest after a run.
