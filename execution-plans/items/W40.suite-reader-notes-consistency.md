# W40.suite-reader-notes-consistency — the differences, and which app's way wins

Owner's Notes session 2 (2026-11-06), rows 12, 13, 21 (with 3 and 26): "we need more standardization in appearance
and functionality across Reader and Notes. This is important." Read from the sources on 2026-11-13.

## The list's tags (row 12) — the Reader wins

| | Reader | Notes before |
|---|---|---|
| Cell | chips (`TagChips`), wrapping at the column width; the row grows | the tags joined by commas, one line, cut in the middle |
| Chip | rounded rectangle r 4, accent at 0.3, list font, outlined on a selected row | none |
| Row height | grows with the chips | fixed |

Why the Reader: the owner's own example, and a cut line hides tags. Notes gets the same chips, drawn by the same code
(`TagChips` moves to ArchiveCoreUI), and a row as tall as its tags. Notes keeps fixed heights for every other row: its
heights are worked out from the chips' layout at the Tags column's width (`heightOfRow`), not by Auto Layout, which
collapsed its rows once (W40.fix-notes-row-clip).

## The tags bar under a note (row 13) — the Reader's chips, the full width

Before: "Tags", then the tags as capsules (accent 0.15, caption font) in what was left of the width, then a 180 pt add
field at the right. After: the tags run across the whole bar, drawn as the Reader's list draws them (the shared chip
look), each with its ✕, and the add field follows the last tag on the same flow, as typing follows the tokens in the
Reader's tag field. The filter bar's tag field (`NoteTagChipsField`) uses the same chip.

## The filter bar (row 21) — the Reader's arrangement

| | Reader | Notes before |
|---|---|---|
| Layout | `FilterBarLayout`: one row that wraps, keeping each control (no focus loss) | `ViewThatFits` (rebuilds the fields: the Reader's W40.fix-reader-filter-focus) |
| Row 1 | read state · Q1 Q2 Q3 · tag filter · Dates · Save as Smart Folder / Clear All at the right | kind · search · Advanced icon · count · save icon · Clear All |
| Row 2 | file name · OCR search · Advanced… | ★3 ★2 ★1 · From/To year fields |
| Row 3 | In effect | tag filter on its own row |
| Row 4 | | In effect |
| Quality | "Q1"…"Q3" toggle buttons | yellow stars ★3…★1 |
| Dates | a Dates button with a popover (From, To, Clear, Done); the years show on it once set | two year fields in the bar |
| Save / Clear | text buttons, at the row's right, shown while something is in effect | an icon and a button, always shown |

Notes now uses the Reader's layout and order: row 1 kind (Notes' counterpart of read state) · Q1 Q2 Q3 · tag field ·
Dates · Save as Smart Folder / Clear All at the right; row 2 the search field and Advanced…; row 3 In effect.
`FilterBarLayout`, `FlowLayout` and the In effect chip move to ArchiveCoreUI and both bars use them. The quality
toggles become Q1–Q3 buttons because the quality is the same thing in both apps (1–3, the tag Q1–Q3), and the
Reader's order (Q1 first) is the one its row pop-up and editor use. Notes' item count stays, at the right of row 2 (the
Reader's bar has none; Notes shows its count nowhere else).

Left different, on purpose:
- **All/Any beside the tag filter.** The Reader has it; the owner ruled it out of Notes' bar (notes-1 row 37: "That
  should be available in Advanced Search"). Notes keeps the ruling; whether the Reader drops its picker is asked in the
  Daemon Report, since Smart Folders store it.
- **The tag filter's field.** The Reader's is a bounded token field (its BUG-3 fix); Notes' chips wrap under the
  owner's notes-2 row 20 (W40.fix-notes-tag-fields). Both now draw the same chip.
- **File name vs keyword search.** Notes has no files; its one search field is the Reader's OCR field's counterpart.

## The side panel — one name and key

Both apps call it the Inspector on ⌥⌘I (the Reader's half shipped in W40.reader-commands-table); nothing to change.
