## Blocked: the byte-preserving writer backend (owner gate W44.reocr-processor-owner-ok)
Plan §5 chose a bundled PDFium incremental-save adapter. Two findings stop it:
1. This session's permissions refused downloading a pinned PDFium build from GitHub (a third-party binary).
2. A dynamic `libpdfium.dylib` cannot load in the Processor: hardened runtime + the self-signed "Archive Suite Dev"
   certificate has no Team ID, so library validation rejects it (the same reason as `ENABLE_DEBUG_DYLIB: NO`), and
   Release may not carry `disable-library-validation`. A static build is needed. Candidate:
   paulocoutinhox/pdfium-lib release `8046d`, `macos.zip` (13.7 MB). The only PDFium on this Mac is pypdfium2's
   dynamic copy in bench venvs (bblanchon chromium/8076), unusable for the reason above.
