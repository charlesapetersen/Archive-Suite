## One file's run (session 2, checkpoint 6)
- `ReOCR/ReOCRJob.swift`: `start` validates, prepares (backup + journal) first, then works from the verified copy's
  bytes; each selected image page reaches the injected reader as its own embedded JPEG (one unrotated JPEG image
  XObject) or a 300 dpi rendering; never a text page. All selected pairs read → replacements → proven candidate;
  any failed pair → no candidate. `accept` → `ReOCRFileWriter.accept`; `reject` → new terminal `rejected` phase
  (file untouched, copy kept; recovery reports `.rejected`).
- The JPEG fast path (`embeddedJPEG`) takes a page only when its content is `q`/`Q`, rectangular clips holding the
  whole image (PDFKit writes `0 0 W H re W n` round every page), one upright scaling `cm` inside the crop box and one
  `Do` of its only XObject, an unmasked upright JPEG; else a 300 dpi rendering. On Processor output the reader gets
  the source JPEG byte for byte. Page images are 0600 in a 0700 scratch folder and removed after each reading. A
  failure after `prepare` records the operation rejected; the backup's digest is checked against the journal; a
  failed `prepare` removes its half-made copy.
- Self-test `scripts/test-reocr-job.sh` (`ReOCRJobTestDriver`, fake reader, 42 checks). Opus Tier-2 review: no HIGH;

## After publication (session 2, checkpoint 8)
- `ReOCRJob` now needs the connected shared support folder and the file's archive root (`Root(guid:url:)`), and
  refuses before keeping or reading anything without them. `start` records the flag generation and whether the file
  was flagged. `accept` publishes, writes the Core `ImproveOCRReceipt` (`Receipts/<op>.json`: root GUID, relative
  path, text pages, before/after SHA-256, outcome; no text), then `clearFlag`: under the flag lock, only the
  reviewed generation (`begin(ifGenerationIs:)`), every spelling of `OCR Poor` removed through
  `CoordinatedTagWriter`, the value read back committed; a failed tag write reconciles at once. Outcomes:
  cleared / notFlagged / changedSinceReview / failed, reported rather than thrown ("text accepted; flag still needs
  clearing"); `clearFlag` and `writeReceipt` retry alone.
- A clear only happens when the file was flagged at review (a flag set during the read, in or outside the suite,
  stays), the generation is the reviewed one or this operation's own earlier attempt (intents and events carry the
  journal's operation ID, so a retry or an interrupted clear resumes), and the file is still the published inode.
  Unreadable tags at review refuse the run. Receipts compare by revision, not date, so a retry or rebuilt receipt
  is the same receipt. `accept` throws `publishedButUnverified`/`publishedRecordPending` after a swap: launch
  recovery (not built yet) must then finish the receipt and the flag. Flag outcome is not journalled yet, so after a
  relaunch only launch recovery can retry it.
- Job self-test (case 8 adds: Finder-set flag during the read left; interrupted own clear resumed with no barrier;
  retry of a finished clear reports cleared). Core `ImproveOCRReceiptTests`; whole Core suite green; Reader/Notes
  build-for-testing green. Opus Tier-2 review: one HIGH (flag set after review on a file with no events would be
  cleared) and three MED (retry never succeeds after its own failure; receipt retry failed on its date; accept's
  post-swap throws undocumented) fixed; identity guard (published inode) added.

## Job record and launch recovery (session 2, checkpoint 9)
- `ReOCRJob.Record` (`Versions/<op>/job.json`, written after `prepare` through `ReOCRFileWriter.writeRecord`, which
  refuses the journal's and the backup's names): key, reviewed generation, flagged-at-review, text pages, receipt
  written, flag outcome. `finish(journal)` writes a missing receipt and retries a failed flag clear, recording each;
  `accept` uses it (with the review as fallback) and reports a failed record save. `ReOCRJob.recover()` runs the
  writer's recovery, then `finish` for every published operation, once. A finished clear of this operation followed
  by a flag put back outside the suite is left ("set again after it was cleared").
- Job self-test case 9: a crash past the swap → recovery publishes, writes the receipt, clears the flag; a second
  recovery changes nothing; a flag put back after the clear is not cleared again; the journal cannot be overwritten.
  Opus review: no HIGH; one MED (a re-run could undo a flag put back in Finder) and LOWs fixed. Not done: a receipt
  for a published operation that recovery reports as a conflict (stray temporary); recovery under the flag lock.

## Restore (session 2, checkpoint 10)
- `ReOCRJob.restore(acceptedOperationID)`: refused unless the accepted journal is published, not yet restored, the
  live file is exactly the accepted revision and the kept original matches its digest; then its own
  `ReOCRFileWriter` prepare + accept with the original bytes (so the accepted revision is kept too and current
  tags/dates are carried over), a `restored` receipt, and a re-flag only when the original was flagged, acceptance
  cleared it, and the last flag event is still that clear (canonical `OCR Poor` added through `CoordinatedTagWriter`).
  Records link both ways (`restores` / `restoredBy`); launch recovery writes a restore's receipt as `restored` and
  clears nothing.
- Job self-test case 10 (73 checks in all): original bytes back with later tag edits kept and the flag re-added;
  accepted revision kept; restore receipt; recovery afterwards changes nothing; a second restore and a restore of a
  changed file refused; no re-flag after a later flag action or when the original was not flagged.
- Opus Tier-2 review: no HIGH; fixed MED (digest re-checked against what `prepare` kept, so a change between the
  check and `prepare` is refused; a restore's own interrupted re-flag is reconciled by recovery) and LOWs (a failed
  restore before the swap is rejected rather than left for review; a restore cannot be restored). Open, safe side: a
  restore whose publication recovery has to finish does not re-flag, and an acceptance whose clear completed via its
  own reconciled attempt is not re-flagged.
