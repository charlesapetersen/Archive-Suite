# W9.g16-flake — session notes

## 2026-10-10 (session 2)

- **Reproduced.** `TEST_ITERATIONS=15` (new `vm-gui-runner.sh` override) of G16 alone, with three `yes` CPU hogs
  in the 4-core guest: iteration 11 failed. With the new value assertion the field held only `"zoter"` —
  the first five keystrokes of the link landed, then keyboard focus left the field. Attach stays disabled
  (`ZoteroSelectLink.parse` fails), which is why the old failure read as "chip did not appear".
  The field kept its partial text, so the inspector was not rebuilt; something took first responder.
  Rate: 1 in 15, then 0 in 25 — roughly 1 in 25-40.
- **Ruled out:** a late body load. G16 waits for the clipboard banner, and the banner is set only after
  `bodyEditor.select` returns (`NoteEditorPane` `.onChange(of: selectedItemID)`), so the body is always
  loaded before the field is clicked. A DEBUG 3 s body-load delay test was written and PASSED against
  unfixed code, i.e. the editor's one-shot initial focus does not steal from a focused field in that
  order. Both the delay seam and that test were dropped.
- **Next:** the G16 assertion now prints the element holding keyboard focus, whether the editor body
  changed, and the window titles. One failing iteration names the thief.
