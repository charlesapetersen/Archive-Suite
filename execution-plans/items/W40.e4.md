## Findings about the method

- The Reader and Notes app-hosted unit runs write NO profile on the host (signed, sandboxed test host; ProfileData
  stays empty; xccov: no coverage archive). In the VM (ad-hoc build) they do, so unit bundles run in the VM.
- Processor drivers on the host: the instrumented build ran all 28 drivers (4 failed under it: batch-resume,
  collection-organize, ocr-page-kind, segmentation-chooser — slower instrumented code, not checked), and wrote
  8,073,312-byte profiles, but `llvm-profdata` refuses every one: "malformed instrumentation profile data: number of
  counters is zero" (the same tool reads the ArchiveCore test run's profile). Build used
  `CLANG_COVERAGE_MAPPING=YES CLANG_COVERAGE_MAPPING_LINKER_ARGS=YES`; all three modules got
  `-profile-generate -profile-coverage-mapping`. `--binary-file` correlation: "could not find section
  (__llvm_covdata)". Unresolved. Next ideas: build the Processor through `xcodebuild build-for-testing
  -enableCodeCoverage YES` (test-only flag is accepted there) and run the drivers against that product; check
  whether a prebuilt static library in the link carries its own profile runtime/version.
