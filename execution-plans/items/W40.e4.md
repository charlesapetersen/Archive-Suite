## Findings about the method

- The Reader and Notes app-hosted unit runs write NO profile on the host (signed, sandboxed test host; ProfileData
  stays empty; xccov: no coverage archive). In the VM (ad-hoc build) they do, so unit bundles run in the VM.
- Processor drivers on the host: a plain `build` with `CLANG_COVERAGE_MAPPING=YES` wrote profiles `llvm-profdata`
  refused ("malformed … number of counters is zero"). `build-for-testing -enableCodeCoverage YES` into the same
  `macOS/build/DD` writes readable ones (probe: test-segment-json.sh), so the script now builds that way. Under the
  first (refused) build, 4 drivers failed: batch-resume, collection-organize, ocr-page-kind,
  segmentation-chooser — check whether they fail on a normal build before calling it a regression.
