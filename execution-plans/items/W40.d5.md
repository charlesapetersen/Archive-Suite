ledger rows for the tag card / finalize / staging.

Design worked out (not yet tried):

1. **Topology.** "By hand" on the Mac means GUI, so the Mac app runs in the Tart VM (`archive-gui-runner`),
   driven by a new XCUITest in `ArchiveProcessorUITests`; the emulator stays on the host with `-no-window`
   (`android-ui-drive.sh`, unchanged). The driver dials `MACHOST=10.0.2.2` (host loopback), so bridge the host
   port to the VM: a host-side TCP relay `127.0.0.1:<port>` → `$(tart ip archive-gui-runner):<port>` (socat if
   installed, else a small python relay). Check first that the emulator → host loopback → VM path carries the
   LAN protocol at all.
2. **Mac launch.** The UITest launches the app with `LIVECAPTURE_AUTOSTART=1` + `LIVECAPTURE_READYFILE` +
   `LIVECAPTURE_TESTOUT`-style isolated output under the test's scratch root, and WITHOUT the two auto flags.
   The host orchestrator reads the READY file over `tart exec` to get port + token, starts the relay, then
   `inject-flow` with real images (copy 3-4 from `Test Files` into a fixtures dir with a small ground_truth.json
   in the `e2e-fixtures` shape). Look at how `e2e-phone-mac.sh` lines 150-215 sequence this; reuse its pieces.
3. **Hand review.** The XCUITest waits for the tag card, types real values (subject, date, quality), skips one
   card on purpose, then clicks Finish/finalize; then asserts the output PDFs' tags match what was typed
   (decode xattrs in the VM with `xattr -px` → `plutil`, against `SPEC/tag-format.md`).
4. **Stage-for-later.** Second run with the mode set to Stage for later (Settings, or the first-run chooser —
   drive it by hand): no OCR, $0; assert the staged hand-off appears where Process Files picks it up.
5. **Trash ordering.** Originals are backed up then moved to the Trash at finalize. Prove order from the app
   log (NSLog lines) plus file timestamps: each output PDF's mtime/birth precedes its original's Trash arrival;
   also force one output write to fail (if a seam exists) and show the original stays put.
6. **Money.** Live mode OCR needs a key in the VM: pass `LIVECAPTURE_OCRKEY` via the launch environment only
   (never write it to a file in the VM; redact logs as `e2e-phone-mac.sh` does). gemini-2.5-flash-lite on 3-4
   images is cents, well under $3. Stage-for-later costs nothing.

Next step: confirm (1) — boot the VM, run a trivial listener in it, and `curl` it from the emulator through the
host relay. If the path does not work, fall back to running the emulator against a headless Mac app on the host
for the capture leg and doing only the review half in the VM, and say so in the evidence.
