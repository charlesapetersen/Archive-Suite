# W49.reader-catalogue-scale — session notes

Session 1 (2026-11-25, Opus 5.5), branch `wt/catalogue-scale-*`.

Design as built:
- ArchiveCore `CatalogueReadMemory.swift`: `RememberedRead` per path (PDF FileVersion + identity, companion
  FileVersion + parsed record, failure) and `ReadMemory` per root instance + root directory identity.
  `CatalogueReader.snapshot(_:remembering:)` reuses identity/record only when the freshly opened descriptor's full
  FileVersion matches; `snapshot(revising:inventory:rereading:)` carries unnamed paths without opening them and
  re-resolves owners; `rememberedSnapshot(_:)` builds a snapshot from memory alone (warm rows, never written from).
- Reader `ReaderCatalogueScan`: `run(memory:warm:onWarm:)`, `revise(...)` for an event batch (nil → full pass),
  `cache(instance:)`; `ReaderCatalogueCache` (binary plist, `catalogue-cache-v1/<instance>.plist` beside the
  library index; nil in the unit-test host and for fixture roots without the scratch-index key) and its writer.
- `ArchiveLibrary`: catalogue FSEvents batches go through `startCatalogueRevision` (watch-work lane), a full
  rescan only for dropped events or a declined revision; first pass of a root publishes the cache's rows as
  `.revalidating`.

Measured (Debug, unit host, 1,000 PDFs, 250 companions): cold pass 213–253 ms, pass with memory 149–180 ms,
one-companion revision 47–49 ms.

150k synthetic tree (124,647 rows, Debug, first build): cold 53.1 s, with memory 36.0 s, one-path revision
8.8 s (whole-list rebuild + localizedStandardCompare re-sort) → fixed by keeping the previous order, binary
insertion of new rows and reusing every stand-alone row (1,000-row revision 49 → 6.5 ms). Cache 49 MB,
encode 2.3 s, decode 2.3 s, warm rows 2.6 s.

Tier-2 review (Opus subagent, read-only) — fixed: an incomplete walk is never carried (revise → nil); warm cache
ignored when the root path moved; cache tied to the app build; a new hard link or a vanished invalid row asks
for a full pass; the pair memory gets only re-read pairs. Refuted: overlap of passes and revisions, warm after
real, edit authorisation from memory, event shapes, safety.

Checkpoint 1 committed. Next: full Reader bundle, Notes/Processor builds (shared ArchiveCore), 150k rerun,
follow-up item for edit refresh, ship.
