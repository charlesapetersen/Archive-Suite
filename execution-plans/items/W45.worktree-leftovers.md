nothing is committed-but-unmerged; the risk is edits that were never committed. Five clean, merged worktrees were

## What the engine should do

1. For each worktree, work from its backup patch, not from the live directory. Re-run the comparison against the
   current `origin/main` (it moves), then decide per file: already landed, superseded by what main has now, or still
   wanted.
2. Land what is still wanted through the normal path: a fresh worktree from `origin/main`, apply, build and test,
   commit, push. Never `git checkout origin/main -- .` in a worktree with uncommitted edits.
3. Remove a worktree only after every change in it is landed, superseded, or confirmed junk, and its backup is
   intact. Delete its local branch with `git branch -d`.
4. Anything the engine cannot place with confidence, or that would mean discarding unlanded work, goes to the Daemon
   Report as a question for the owner; do not discard it.
5. Leave the stale `codex/*`, `worktree-agent-*` and older `wt/*` branches alone unless a worktree is removed with
   them; they were not examined.

Done when: no `suite-wt-*` directory is left with uncommitted changes, or each one remaining is named in the Daemon
Report with the question the owner must answer.
