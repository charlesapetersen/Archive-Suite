# Few-shot examples in the Gemini window prompt (W46.seg-adapt-curve-paid)

Generated by `scripts/segbench/seg_adapt_fewshot.py` (method in its docstring). Gemini 3.7 Flash through the Stanford gateway, low reasoning, temperature 0, g1 windows (7 pages, stride 3). The zero-shot column is W46.seg-lincoln-cloud-paid's cached arm; the few-shot column is the same requests with the box's k checked gaps added as text examples (OCR either side of the gap and the archivist's decision). The k gaps are W46.seg-adapt-curve's first random draw, and both columns count them as corrected.

## Findings (rescored on the owner-ruled truth, unsure gaps unscored)

1. **The examples change almost nothing, because zero-shot Gemini already makes very few errors here.** Gemini 3.7 Flash windows get 1-6 of the held-out known gaps wrong on these boxes. With the examples:
   - Lincoln, k=25: 6 errors become 4; fixed 57|58, 86|87; no new false merge; pages exact 86.2% to 87.7%.
   - CREST, k=25: no held-out error changed (1 known-gap error either way).
   - CREST, k=50: no held-out error changed (1 known-gap error either way); pages exact 89.1% to 88.3%, a move outside the held-out known gaps (each arm's own call at an unsure gap counts as right in the conditional reading), so no few-shot gain or loss.
   Each difference is one or two gaps on one draw, which is within what a different draw would move. This run is no evidence that few-shot examples help, and none that they hurt.
2. **The examples did not override the archivist.** Where a listed gap fell inside a window, the model gave the archivist's decision every time, as asked. So the examples need no separate guard.
3. **What follows for the kit.** A user's corrections set the gaps they correct; feeding them back into the cloud
   prompt buys no measurable accuracy here, and it costs input tokens on every window: 1.43x the zero-shot arm's
   input on Lincoln at k=25 ($1.18 for the box), 1.51x on CREST at k=25 ($0.68) and 2.01x at k=50 ($0.88). The review
   screen's disagreement rule (W46.seg-adapt-curve) remains the way corrections pay off. Where few-shot might still
   matter is a box on which the cloud model errs often, as the local models do on Lincoln. No such box is in hand
   for Gemini.
4. **Limits.** One random draw per setting; two public boxes; text-only examples (300 characters of OCR either
   side), with no example images; Gemini 3.7, not 3.8. Lincoln k=50 (about $1.40) was not run, to keep the item
   under its $3 cap. Pages exact and PQ are conditional on each arm's own call at the owner's unsure gaps
   (`score.py`), so the two arms' segment figures are not against one fixed truth; held-out errors are known gaps
   only.

## Measurement card

- **Truth.** The owner's ruled boxes: development Dean, Deaver and Herrnstein, test Stanton and RG165; Stanton carries the owner's 2026-10-31 segmentation-sheet rulings (W46.seg-truth-rescore). The public boxes are agent-audited truths with the owner's rulings on their disputed gaps folded in: Lincoln (`5ba5a0e67380…`: 5 gaps owner-ruled, unsure 76|77, 106|107, 230|231); CREST (`c7a0cfcac896…`: 6 gaps owner-ruled, unsure 45|46, 87|88, 93|94, 110|111). Their other gaps remain agent-audited. Unsure gaps are out of every boundary count; segment figures (pages exact, PQ) are the conditional reading, the route's own call at an unsure gap, so they are not one fixed truth across routes (W46.seg-unsure-mask, `score.py`).
- **Selection.** The k checked gaps are W46.seg-adapt-curve's first random draw, made before any few-shot answer; an unsure gap drawn as an example is listed but counted neither as labelled nor as an error.
- **Comparison.** The same Gemini 3.7 Flash requests (gateway, low reasoning, temperature 0, g1 windows), with and without the k examples; both columns count the k gaps as corrected.
- **Noise.** One draw per setting and single runs: no interval, and the rerun floor (1.4-3.2 points of pages exact a box, SEG-10) is larger than every difference here.
- **Scope.** Whether a user's corrections, fed back as text examples, help a cloud model on two public boxes. Not image examples, not Gemini 3.8, not a box where the cloud model errs often.
