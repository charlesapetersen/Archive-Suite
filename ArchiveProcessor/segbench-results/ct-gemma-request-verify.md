# Gemma label request through the Processor: current against revised (W49.proc-gemma-request-verify)

Generated by `scripts/segbench/ct_gemma_request_verify.py --report` from the run's correctness flags, timings and image checks.

## What was run

The Processor's own label path (`ContainerLabelCapture.readLabel`, the call Process Files and Live Capture share) read 16 held-out label photos (8 box, 8 folder) from the ct-gemma-route-fields panel, each at the bench size (1280 px, the paired validation's input) and as its full-size JPEG original, and each stored turned so that the run had to supply a 0, 90, 180 or 270 degree correction. That is 128 complete pairs of 128 started. Each pair read one copy with the current request (photo first, re-encoded) and the revised one (prompt first; the file itself when it is an upright JPEG within the 1,600 px cap, else the same re-encoding), in a seeded order. Gemma 3 12B (4-bit MLX, pinned snapshot) ran alone on mlx-vlm 0.7.4's server on the app's preset port, found by the app's own server lookup.

## Photo handling

- The revised request sent the file itself for 16/16 bench-size photos needing no correction and for 0 of the others (it must turn or scale those). For 112/112 of those others both requests carried byte-identical photos, so there the requests differ only in putting the prompt first.
- Every sent image was checked against the upright bench page at four turns: 256/256 were upright.
- Turned bench-size photos, re-encoded upright: PSNR against the lossless upright crop median 50.8 dB (min 48.3); the current request's re-encoding of the unturned photo, median 50.8 dB. Both use the app's exact 90 degree turn and JPEG quality 0.9 at the photo's own size.
- Source files unchanged after their reads (SHA-256 before and after): 256/256.
- Collection numbers proposed from Vision + parser where Gemma gave none: current 7, revised 2 reads.

## Measurement card

- **Truth.** The ct-read truth (three-reader drafts, owner sheet rulings) as the earlier route reports scored it; the same eligibility per cell. Neither request drafted it.
- **Selection.** 4 labels for each type and written or blank collection number, seeded (4949) from the 135 held-out photos, by truth alone. These photos also supplied the paired validation.
- **Comparison.** Same app build, server, model snapshot, prompt, temperature 0 and 640-token cap; each pair read the same scratch file. Only the request differs. Full-size originals and turned copies are lossless crops and turns of the same JPEGs (jpegtran, cropped to whole 16 px blocks).
- **Noise.** Small n: one read per pair, no intervals. The paired validation (135 photos) is the accuracy estimate; this run checks that the app reproduces its direction and that turned and full-size photos keep the revised request's behaviour. A difference of a few cells is inside rerun variation.
- **Scope.** mlx-vlm 0.7.4 only; Ollama and LM Studio were not tested. Serial label reads with no OCR model loaded alongside. Model switching is W49.proc-gemma-swap-time. The app-managed reader was not exercised (it keeps the re-encoded photo). The production default stays the current request.
