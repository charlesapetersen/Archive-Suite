# S-002 — independent check of cloud-only PDF downloads

2026-11-21 · Codex (gpt-6.2-sol, medium) · Reader baseline `f8f40d15` · macOS 27.2.1, Xcode 27.2.
Claude Opus 5.5 made the [original reproduction](W49.reader-s002-dataless-viewer.md) in `92568b5f`.

## Method

A temporary, headless, app-hosted Reader test used the same non-corpus OneDrive PDF as the original
reproduction (6,233,249 bytes). It compiled and exercised the Reader's own classes. Before the test,
`stat(2)` and `ls -lO` showed `SF_DATALESS`, the macOS flag for a file whose contents are still in the
cloud. The test set process-level materialization to on to match a normal Reader launch.

1. Open the PDF through `CorpusWalker.withDatalessMaterializationDisabled` as a control.
2. Call `PreviewImagePrefetcher.shared.prefetch(paths: [path])` once and wait for its bitmap generation to
   increase. `PreviewImagePrefetchModifier` calls this on a selection change, including while the preview
   is closed. Check the file flag and evict the download.
3. Verify the file is cloud-only again, then call
   `DocumentViewerModel.load(DocumentSelection(filePaths: [path]))` with a non-persisting model and
   read the loaded page count and file flag. This is the load path shared by the document window and
   Space preview. Release the model and evict the download again.

| Path | Reader result | Cloud-only flag after call | Elapsed |
| --- | --- | --- | --- |
| Guarded PDF open | Returned no document | Set | — |
| Selection prefetch | One bitmap completed | Cleared | 2.74 s |
| Viewer load | 54 pages, no load error | Cleared | 1.32 s |

Both evictions restored the flag. A separate `ls -lO` check after the probe confirmed the PDF was
`compressed,dataless` again. The test called the production entry points directly. The surrounding
windows and adjacent-row behavior were traced in source. The two bitmap callers use the same prefetcher
for adjacent rows when the Space preview is showing and for the document window's neighborhood.

Owner call 30 requires cloud-only PDFs to stay cloud-only through selection, thumbnails and neighbor prefetch.
The document window and Space preview should offer **Download and Show** before fetching the file.
The implementation and regression checks are queued as `W49.fix-reader-dataless-prefetch`.

The headless Reader smoke run reported 1,076 tests, six skipped and zero failures, including the temporary
S-002 test. The write-surface lint and all 29 of its self-checks passed.

## Regression in W49.fix-reader-dataless-prefetch

The app-hosted `PreviewImagePrefetchTests.testCloudPlaceholderStaysRemoteUntilDownloadAndShow`
uses the production APIs on the same 6.2 MB OneDrive fixture, with process materialization enabled.
It checks that the local neighbor produces a bitmap, the cloud file produces none, direct bitmap drawing
still refuses it, and page thumbnails, page counts, Find and the viewer leave the file cloud-only.
It then uses the viewer's download action and checks that the file is local and opens on the requested page.

To repeat the probe, put an already-cloud-only scratch PDF path in `AR_S002_CLOUD_FIXTURE` under
`ArchiveReaderTests.EnvironmentVariables` in a local copy of the generated `.xctestrun`.
Select the probe with `xcodebuild test-without-building -only-testing:ArchiveReaderTests/PreviewImagePrefetchTests/testCloudPlaceholderStaysRemoteUntilDownloadAndShow`
under the heavy lock. Restore the fixture to cloud-only after the test host exits and PDFKit releases it.
Keep the fixture outside the archive.

`CloudDocumentUITests` exercises the document window and Space preview in the off-screen VM.
Each test uses the generated scratch archive, simulates cloud status for one PDF, and verifies the prompt,
the two-page PDF after **Download and Show**, and a second local PDF that opens directly.

On 2026-11-21, both VM tests passed. The four captures show the cloud prompt before the action and the
image page, text page and sidebar thumbnail afterwards. The final headless run passed all 19 prefetch
and rendering tests, including the real OneDrive probe in 2.25 seconds. After the test host released the file,
the fixture was evicted and `stat` again reported `compressed,dataless`. The full smoke suite reported
1,083 tests, seven skips and zero failures. The write-surface lint and all 29 of its self-checks passed.
