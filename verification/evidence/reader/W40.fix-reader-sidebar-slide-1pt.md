# W40.fix-reader-sidebar-slide-1pt — the list's scroll view on whole pixels (VM, 2026-10-31)

A temporary DEBUG trace (removed before shipping) logged, after every run-loop pass, the file list's scroll view frame
in the window, its clip view's frame and bounds, the table's and header's frames, and the Warning cell's window frame,
while the sidebar was hidden and shown four times (`log show --predicate 'subsystem == "w40.slide"'` in the VM).

## Before

During a slide, SwiftUI puts the scroll view at fractional x, and the clip view and table take the remainder on
alternate passes (excerpt, `scroll` = scroll view in window, `clipB` = clip bounds, `table` = table frame):

```
scroll=82.44  clipF=-0.44 clipB=-0.44  table=0.00   warnCellWin=120.00
scroll=240.00 clipF=0.00  clipB=0.00   table=-0.44  warnCellWin=278.00   (next pass: table 0.00, cell 278.44 → 278)
scroll=0.72   clipF=0.28  clipB=0.28   table=0.00   warnCellWin=39.00
scroll=0.00   clipF=0.00  clipB=0.00   table=-0.72  warnCellWin=37.00
scroll=0.00   clipF=0.00  clipB=-1.00  table=-0.72  warnCellWin=38.00
```

The cell's window x goes 39 → 37 → 38 while the slide moves one way: the turn-back the transient recorder reported.
`TableColumnFitter.fit` ran on every pass and changed no column width, so the fitter is not the cause.

## Fix and after

`PixelAlignedScrollView` rounds each frame SwiftUI sets to the nearest backing-pixel edges. Same trace, with
`ONLY_TESTING=ArchiveReaderUITests/TransientStateUITests TEST_ITERATIONS=6`: 618 samples, every `scroll`, `clipB` and
`table` origin a whole point (`grep -o 'scroll=…\|clipB=…\|table=…'` finds no fractional value). 18 tests, 0 failures:
`testCommonTransitionsShowNoTransientState` 6/6 (3 of 6 failed before), `testRecorderCatchesAPlantedFlicker` 6/6, so
the recorder still catches a real flicker.
