**One observation, not a defect.** The sample's tags were stored as bare names (`Unread`); after a Reader write,
every name on the file is stored as `Unread\n0`. That is the system's own encoding of `.tagNamesKey` with no
colour (label 0), the form Finder writes; the names, their order and the file's colour label (FinderInfo,
unchanged) are the same.

## The audit ledger against the disk

The owner's ledger is `~/Library/Containers/com.archivereader.app/Data/Library/Application Support/ArchiveReader/audit-ledger.jsonl`
(562 lines, one live file, no rolled segments). 54 of its lines name a file in `reader-session-2/` (19:09–19:31
local, 51 groups), with the `undoAttempt` and `redoAttempt` markers between them.

- **Every change is in it.** Starting from each file's tags in `reader-sample/` and applying its ledger lines in
  order, each line's `before` equals the state the previous line left, and the final `after` equals the tags on
  disk, names and order, for all 11 files. No changed file is missing from the ledger, and no ledger line names a
  file whose tags did not change.
- **Undo and redo are recorded as the promise says.** Each undo is an `undoAttempt` marker then the `undo` line
  naming the group it undoes (`undoes`); each redo is a `redoAttempt` then the `redo` line (`redoes`).
- **Every forward, undo and redo line carries a bookmark and the file's device and inode**, which durable undo
  checks before it writes.
- **No line is marked `unverified`.**

The owner's ⌘Z straight after quit and relaunch (task 7) undid the change from before the quit, so the ledger was
the source of that undo.
