# W40.fix-reader-advanced-many-rules — Advanced Search with many rules

2026-11-11. The owner, 2026-11-10: rules past the seven that fit "get added for a little bit and then dropped", and
scrolling the rule list did not bring them back.

## 1. Reproduction (VM, AR-GUI-Fixture, `AdvancedSearchUITests.testTwelveAddedRulesStay`, before the fix)

Twelve rules added one by one, each from the last row's +, each given a word. No rule was lost: all 15 rows (3
starter + 12) stayed in the form after each count and after a 3 s pause, and all 12 came back when the form reopened
on the search in effect. What did happen: the rule list was fixed at its 260 pt ideal height, about eight rows, and a
row added below them was put out of view without the list scrolling to it. The 7th added row's text field sat at
y 477, under the list's clip at y 466; XCUITest could not type into it ("Neither element nor any descendant has
keyboard focus"). Scrolling the list by hand did reach every row in the VM. So what the owner saw is most likely the
new row disappearing below the visible rows; the report that scrolling did not bring them back was not reproduced.

At 116k synthetic rows (`ReaderAtSizeTests`, -O, this session QoS-clamped), twelve file-name rules counted one by
one: median 1,139 ms per count, off the main actor already (W40.fix-reader-change-incremental), but the next edit did
not stop a running count.

## 2. The fix

- The list grows with its rows up to 420 pt and scrolls to each added row (`ScrollViewReader`).
- The form edits an `AdvancedSearchDraft` the request holds, not view state, so a sheet presented again or rebuilt
  resumes the edits rather than the opening rules.
- `countMatches` stops its index queries and its row pass when the next edit cancels it: 0.1 ms to return.
- The row pass tests prepared rules (inactive rows taken out, names trimmed once; `prepared()` is checked against
  `matches` rule by rule) across the cores in chunks: median 216 ms, max 368 ms for 116k rows with 12 rules.

## 3. After (VM, the same test, a foreign tag change at rules 5 and 9)

All three AdvancedSearchUITests pass. Every added row is in view without scrolling, the list grew past its first
height, and all twelve stay and come back on reopening. Screenshot: `W40.fix-reader-advanced-many-rules-twelve.jpg`
(twelve rules shown at once, the twelfth just typed).
