# W40.fix-reader-tag-entry — tag entry: several tags in a row, a space that ends a completion, autocomplete in Edit Tags

2026-11-05, Tart VM `archive-gui-runner`, generated scratch fixture (`AR-GUI-Fixture`), Reader Debug build.
Owner session reader-1, rows 28, 29 and 36 (`verification/sessions/reader-1-returned.md`); ledger rows R-22, R-23.

## The causes

- **Row 36, a space could not end a completion.** The completion lookup trimmed the substring it was given, so
  "Civ " was looked up as "Civ", still matched "Civil War", and the token field put the suggestion back over the
  space. Only leading whitespace is dropped now (`Views/TagEntry.swift`), so "Civ " completes only subjects that
  really start "Civ ". Subjects are often two words, so a space stays a space: it does not end the tag.
- **Row 29, the field let go after every tag.** Return ended the edit (`W40.fix-reader-inline-keys` made it commit
  by handing focus back to the list). Return with text typed now writes the tags and keeps the keyboard in the
  field; Return with nothing typed still ends the edit. Leaving the field writes what changed since the last Return.
- **Row 28, no autocomplete in Edit Tags.** The sheet's field was a SwiftUI `TextField`. It is now a token field
  (`Views/SubjectEntryField.swift`) with the same completions. Return or a comma adds what is typed and keeps the
  keyboard; Tab adds the suggestion; leaving the field or clicking Done adds what is still typed (typed text sticks,
  as in the list). While a subject is being typed, Return belongs to the field rather than to Done.

**The typed case stays.** The token field writes a filled-in completion over the typed text, so a case-insensitive
one turned "w40d8 m" into "W40d8 M": once Edit Tags autocompleted, a case variant could not be typed there and the
sheet's case warning (R-27) never showed. The whole Reader UI lane caught it (`TriageJourneyUITests` step 6a: the
variant file got `W40d8 Merge`, a no-op). The list's field and the sheet now fill a completion in only when it starts
with exactly what was typed; others still show in the list, for ↓ and Return (`TagEntry.filledInIndex`). The tag
filter keeps filling in the first match whatever its case, as a filter names a subject that exists.

Tab and → need no code: with a suggestion showing, the token field turns it into a token on Tab (and moves to the
next control), and → moves the caret past it. A first version hooked Tab in the delegate; the VM run showed the hook
never runs while the suggestion list is open, so it was removed.

The mid-edit write is new: before, a tag cell wrote only once its edit had ended. A write that re-sorts or filters
the list (sort by tags, a tag filter) would apply a new snapshot under the open field editor, and the reused cell
could keep this file's id while showing another row. While a tag cell is being edited the list now keeps its rows
and snapshot, and takes the new ones on the turn after the edit ends (`AppKitTableView.Coordinator.showRows` /
`catchUpRows`). A Return write that fails leaves the edit's base where it was, so leaving the field tries again.
