# W40.fix-reader-list-recompute-at-size — a tag edit and a sort change at corpus size

recheck (builder is not verifier).

**What changed.**
- `LibrarySort.sorted` is a decorated sort. Each key is computed once per row. Each string key becomes its
  `localizedStandardCompare` rank from `CollationRanks` (`Core/CollationRanks.swift`), which remembers ranks
  across sorts, so the n·log n comparisons compare integers. Paths are ranked only for rows that tie on every key.
  `LibrarySortDecoratedTests` pins the result to the old comparator: 60 random rounds over every field and
  direction, missing facets, names that collate equal, a tag edit and a rename, and the cache's growth and reset.
- `ArchiveFile` stores `path` (and its UTF-8 hash) and `name` as native UTF-8, made once at init. The filters, the
  change signatures and the sort read them. The synthetic tree's paths are 42% non-ASCII. `String` hashes such
  strings by normalizing them on every hash, and `URL.path` is rebuilt on every access. So the rank cache keys on
  bytes (`UTF8Key`), and the signatures XOR the stored hash.
- The table coordinator keeps the displayed rows array and an id→row index. It rebuilds the index only when the
  snapshot changes, so a tag edit, which keeps every id where it was, no longer rebuilds a 116k-entry dictionary.
  `syncSelection` and scroll-to-row look up the selected ids instead of walking every row.
- `ContentIndexer.pruneIfSettled` takes an array and works out the absent set in its detached task. The
  two-emission decision itself is unchanged.

**What it does not remove.** A key is ranked the first time a sort sees it, once per session. That costs about what
one sort cost before: 0.74 s for 116k names, and 2.7 s the first time a date sort ranks the paths of this tree's
mostly-tied rows. Quality, read state, type and file tags take 0.08–0.23 s the first time. The first list after
launch therefore still pays the name ranking, as it paid the old default sort. The table's snapshot after a re-sort
(320 ms, every row moving) is `NSTableViewDiffableDataSource`'s own work, and was not changed.
