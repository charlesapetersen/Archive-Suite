# W40.fix-reader-vm-suite-red — the three red Reader UITests (2026-10-31)

All UI runs are in the Tart VM (`ops/gui/vm-gui-runner.sh reader xcuitest`).

## Run alone at the start, on main (87201576)

`LayoutGuardUITests/testMainScreensLayOutInLightMode`, `TransientStateUITests`,
`TriageJourneyUITests/testTriage…`: 4 tests, 2 failures. The layout guard failed only on the tag-cloud screen at

## Cause 1: the layout guard's `1983`

The guard's tree (xcresult attachment, tag cloud, light, settled) for `00006 IMG — Brown.pdf`:

```
cell (760,324 195×20)
  textField#ar.cell.tags.00006 IMG — Brown.pdf "￼￼" (761,325 193×18)
    textField "Orwell Reference" (761,325 141×16)
    textField "1983" (761,341 68×16)
```

The two children are NSTokenFieldCell's native tokens, which is what accessibility reports. The Reader draws its
own chips instead (W40.fix-reader-selected-row-contrast). The chips are narrower than native tokens, so at 193 pt
they fit on one line while the native tokens wrap to two. The row was measured for the chips, one line, and the
second native token sat below it. A user sees nothing wrong. VoiceOver is told the subject is below its row.

The first fix tried was a `WrappingTokenField.accessibilityChildren()` override that reported the drawn chips. It
was wrong. NSTokenField answers accessibility through the legacy attribute API, which calls the override again,
so `super.accessibilityChildren()` recursed until the stack overflowed (crash report
`ArchiveReader-2026-10-31-2135242.ips`, `Thread stack size exceeded due to excessive recursion` at the override).
Without `super`, XCUITest no longer found the field at all: TriageJourney's `ar.cell.tags.*` lookup failed in every
row ("no Unread file with a unique name is visible in the list"). Two VM runs confirmed this.

What shipped: the chips take at least the native tokens' line count at every width (`chipsLayout` searches for the
widest narrower width that gives them that many lines), and the field is at least as tall as the native layout
(`height(editing: false)` is the larger of the two). Native heights are cached by width per subject set and font.
`testChipsTakeAtLeastTheNativeTokensLines` checks three subject sets at every width from 120 to 600 pt.

## Cause 2: the missing Box 2 folder and smart folder

`ar.showSidebar` and `ar.showTagCloud` are `@AppStorage`, and nothing reset them between UI tests.
`NavigationUITests.testSidebarToggles` hides the sidebar and checked once after 0.5 s. When that check failed, the
test stopped with the sidebar hidden (`continueAfterFailure` is off), and TransientState and TriageJourney, which run
after it, launched with no sidebar. That fits both reported symptoms, and the visual tour, which shows the sidebar
itself, still showed Box 2. A fixture launch now resets both panes to a fresh install's (`ReaderUITestDefaults`,
renamed from `ReaderAppearanceUITestDefaults`). `testSidebarToggles` waits up to 3 s for the slide-out. Unit test
`testAFixtureUITestLaunchShowsTheSidebarAndClosesTheTagCloud`.

## Not this item: the sidebar slide's 1-pt step back (filed `W40.fix-reader-sidebar-slide-1pt`)

`TransientStateUITests/testCommonTransitionsShowNoTransientState` failed in 3 of 6 runs today, each time on a

- show: `AXStaticText x 39→135→134→279→279` (the Warning cell's text)
- show: `AXStaticText x 71→312→311→311→311→312` (a Date cell's text)
- hide: `AXCell x 898→723→724` (a Quality cell)

Every one is a 1-pt turn-back inside the table's scroll view, for one to three passes. THE SLIDE ALLOWANCE
deliberately does not cover a coordinate that itself travels, and the transient rule was left as it is. It passed in
both whole-suite runs.
