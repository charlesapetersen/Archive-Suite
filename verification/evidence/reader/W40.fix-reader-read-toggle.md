**What the VM found that the unit tests could not:**

1. NSTableView takes a press on a plain (non-control) cell view itself, so the cell's own `mouseDown` never ran and
   the first VM run wrote nothing. `ContextMenuTableView` now hands a press inside a Read cell to the cell.
2. `NavigationUITests.waitForTags` built its `URL` once and polled it; a reused `URL` caches resource values, so
   a write landing after the first poll (the click waits out the double-click interval) was never seen. It now
   reads through a fresh `URL` each pass.
3. An earlier test can leave the tag cloud open (`@AppStorage`), which pushes the Read column off screen; the two
   tests close it first and assert the cell is hittable.

Unit: `ArchiveReaderTests/ReadToggleTests` (5 tests; each failed before the fix: the hit view was a plain label,
so no menu and no write).
