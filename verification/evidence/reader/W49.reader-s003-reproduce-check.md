# S-003 — Reader shows “No matches” when the OCR index cannot open

2026-11-21 · Codex (gpt-6.2-sol, medium) · baseline `85f7a7a8` · headless Tart VM.
[Claude Opus 5.5’s original model reproduction](W49.reader-s003-dead-index.md) is in `a4ea1d4b`.

## Reproduce in the Reader window

1. Run `CORRUPT_INDEX_FIXTURE=1 ops/gui/vm-gui-runner.sh reader xcuitest` with the
   `ContentIndexFailureUITests.testCorruptIndexWarningRetractsAfterScratchRepairAndReindex`
   pre-repair steps temporarily extended. The runner sets `AR_GUI_CORRUPT_INDEX=1` to build
   the generated scratch archive and seed its disposable SQLite cache with 1 KiB of invalid bytes.
2. Before the test repairs the cache, wait for rows and the amber “Search index unavailable”
   warning. Click the normal **Search OCR text** field (`ar.filter.ocr`) and type `California`.
3. Wait for `ar.empty.filteredOut` and capture the window before the test replaces the cache.
   Check that there are zero table rows and that `ar.status.indexFailure` is still visible.

## Observation

The list initially showed all 12 scratch files. Typing the OCR query left zero rows. The overlay
said **No matches** and displayed `The OCR search “California” hides every file.` It offered
`Clear Text: “California”` and **Clear All**. The status bar still said “Search index unavailable”.

[Screenshot of the Reader window with the failed index](W49.reader-s003-before-repair.png).
The PNG is a crop of the guest screenshot, including the search field, empty-list message and
status bar.

The first capture verified the overlay and zero rows. Its probe stopped because it looked up the
clear button by the abbreviated label “Clear Text”. With the actual accessibility identifier,
the rerun clicked the button and brought back all 12 rows while the warning persisted.

For the final control, the test replaced only the marker-checked scratch cache with an empty file
and used **File ▸ Rescan Archive Folder**. The warning cleared. The same query then showed 10 of
12 rows and a keyword-in-context snippet containing “California”, proving the matching text was
in the fixture. The focused off-screen test passed in 22.46 seconds with zero failures or skips.

The Reader unit smoke suite reported 1,075 tests, six skipped and zero failures. The write-surface lint
and all 29 of its self-checks passed. The temporary probe was removed after the run. The existing
`DeadIndexEmptyListSuspectTests` model check remains for the follow-up.
