# W48.appearance-verify — the independent re-check of R-48 (2026-11-04)

Phase rules 6 and 7 (`execution-plans/verification-phase/01-daemon-plan.md`): a session that did not build the
Appearance setting re-runs its checks at HEAD in the Tart VM. The expected outcomes below were written from the
ledger row's promise before the code or the tests were read (rule 3).

## Expected, from the promise

1. Options shows Appearance with three values, System, Light and Dark; System is the default.
2. With a sheet and Settings open, picking Dark turns every open window dark at once, without a relaunch; Light
   turns them all light; Dark again, dark again.
3. Quit and relaunch with Dark stored: the first window is already dark (the choice is applied before it draws).
4. System follows the guest's appearance: light under a Light guest, dark under a Dark guest.
5. `-ArchiveUITestAppearance light` over a stored Dark gives Light: the test argument wins.
6. `AccessibilityAuditUITests` and `VisualReviewUITests` pass in Light and in Dark when the mode is set through
   the setting, and the Dark tour's screens show readable text with no light-only colour left over.

## System under a Dark guest

The builder's runs only ever had a Light guest, so "System follows the guest" was only seen agreeing with Light.
The guest was booted headless, given `defaults write -g AppleInterfaceStyle Dark`, stopped, and
`AppearanceSettingUITests` run again: 3/3 pass, and System with nothing stored reads 0.152 (dark), against 0.825
under the Light guest. The guest was then put back (`defaults delete -g AppleInterfaceStyle`, read back as absent).
The same was done for Notes and the Processor.

## Verdict

Every expected outcome holds at HEAD. R-48 moves to `works`.
