# W40.fix-reader-redo — Redo Tag Change (⇧⌘Z)

Owner session reader-1, row 21 ("Undo works; there is no Redo"). Ledger row R-21.

## What changed

- Tags ▸ Redo Tag Change (⇧⌘Z), from the list and from a document window (which names the files, as undo does).
- Redo is the undo of an undo. An undo's own ledger lines carry the inverse of what the undo wrote; redo applies
  it with `TagWriter.applyOccurrence(undoing:)` against the tags before the undo, so it carries every guard undo
  has: §6 identity (path, inode, bookmark), the main archive, the fresh read, no token past its count before the
  undo, the label only while it still reads as the undo left it.
- `beginRedo` writes a synchronized `redoAttempt` marker before the first write; the redo itself is journalled like
  a forward action (intent / done), its lines carry `redoes`, and it is an undo source again.
- `AuditLedger.redoGroups` offers the completed undos newer than the newest forward change (a new change ends the
  redo history), minus those a redo consumed; the same barriers stop it as stop undo. A partly failed redo keeps
  the files that may pass for "Redo again to retry".
- `TextUndoGuard` takes ⇧⌘Z in an editable text field too, so it redoes the typing and never a tag change.

  file is refused, an interrupted redo is never offered again, a partly failed redo retries only the failed file,
  an unclosed redo is a barrier. `TextUndoGuardTests` extended for ⇧⌘Z. Whole `ArchiveReaderTests`: 588 green, no
  new warnings.
- VM (`ONLY_TESTING=ArchiveReaderUITests/UndoFocusUITests ops/gui/vm-gui-runner.sh reader xcuitest`):
  `testShiftCommandZRedoesTheTagChangeAndBelongsToTheFocusedField` passes — ⇧⌘Z from the list redoes a Mark
  Read/Unread on disk, ⇧⌘Z in the file-name filter redoes the typing and leaves the tags, ⇧⌘Z from the list with
  the filter's text redo pending still redoes the tag change, and ⇧⌘Z right after a relaunch redoes it.
  `testCommandZBelongsToTheFocusedFieldAndWorksAtLaunch` still passes. Not run with the fix switched off; without
  the menu item or the guard the corresponding assertions cannot hold (reasoned).
- Adversarial review (Opus): no defect that writes wrongly or offers a redo twice. Low points accepted: a redo can

  undone; the §9 budgets bound it); an older Reader build cannot read redo lines (no compatibility is owed).
