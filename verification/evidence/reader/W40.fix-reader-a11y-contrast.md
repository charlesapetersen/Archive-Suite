# W40.fix-reader-a11y-contrast — small Reader text clears AA

2026-10-25. Baseline `787f291f`; source and final tests in this commit. Presentation only; no corpus access or
write behavior changed. Original findings: `core/W40.e3-accessibility-audit.md` and
`reader/W40.fix-reader-a11y-labels.md` (paths relative to `verification/evidence/`).

Counts, navigation status and preview/viewer page counters now use primary text. Type and both read states
follow primary/native active/inactive selected text; Unread is semibold so distinction does not rely on an
accent color that fails AA. `ReaderColors` provides opaque dark amber in light and pale orange in dark for
warning/flag ink; selected cells use native selection text. Status warnings and the viewer warning icon use
the same adaptive warning color.

Verification:

- `./test-smoke.sh reader`: 510 tests, 3 intentional skips, zero failures; includes the headless render guards.
  No Swift compiler warnings. Platform AppIntents metadata notices and an unrelated scale-test QoS advisory
  appeared. Log: `ArchiveReader/.maintenance/test-results/smoke-reader-20261025-050903.log` in the worktree.
- `SelectedRowContrastTests`: unconditional 4.5:1 floor for small labels/chip text. Read/Unread and warning/Type
  inks render through ordinary, active, inactive and reused selection states. The old accent-on-selection
  negative control still fails the contrast probe as intended. Unit warning minima: 5.23:1 light / 6.10:1 dark.
  Two actual render attachments inspected (light warning, dark selected row), exported from xcresult because
  direct reads of the protected app-container artifacts stalled; only our stalled copy processes were stopped.
- Final VM: `ONLY_TESTING=ArchiveReaderUITests/AccessibilityAuditUITests ART_DIR=/tmp/w40-reader-contrast-vm-r3
  ops/gui/vm-gui-runner.sh reader xcuitest`: two tests green, eight screens, zero unexpected findings, no
  Reader crash/hang. Scratch synthetic fixture, headless Tart, default blue accent, 1920×1200 at 1×.
- The contrast KnownIssue is removed. Direct screenshot checks measure 76 assigned small text nodes, even if
  Xcode does not nominate them. Every count/status family, both page counters and visible Type/Read/warning
  columns are required. A 1800-pt navigation window makes the actual Type/Read factories visible; the saved
  900-pt window had scrolled them off screen. All eight captures inspected (navigation at full resolution,
  remaining final captures together; all eight first-run captures also inspected individually).
- Write-surface lint, todo-stub check and diff whitespace check pass. Independent source/test review: no open
  findings. No shared-package, project specification, file/tag-writing or isolation changes.

The first unit run exposed an overly strict bare-labelColor oracle: NSTextField draws semantic primary text
more opaquely than resolving the bare NSColor. Actual pixel AA remains unconditional; explicit selected/chip
pair comparisons remain. The first direct VM helper missed SwiftUI AXValue text; it now uses the same
AXLabel/AXValue fallback as the shared audit, and requires each family so missing text fails. Final reruns above
are green. The preceding general main-screen audit also passed at the narrow width.

Limits: this verifies the named small text on these fixture screens and default accent, with inactive/selected
transitions additionally covered headlessly. It does not establish whole-app WCAG compliance, reading order,
or whole-task keyboard access. Shared audit exemptions for native macOS-owned controls remain unchanged.
