# W40.fix-reader-tag-add-speed — measured before changing the path

2026-11-08, same Mac, Debug Reader, scratch files only. No real corpus was opened or written.

The first probe timed `NavigationModel.applyEdit(_:paths:)` in four parts, then ran the next main-loop turn.
Eight additions to one scratch file: callback 12.5–19.6 ms, writer/journal 11.3–18.1 ms, history 0.7–1.7 ms,
next turn 1.1–1.5 ms. This did not reproduce an appreciable wait.

The same probe with 50,000 synthetic, dataless rows and one real scratch target reproduced it:
four additions took 44–60 ms through the callback (including 31–34 ms replacing library rows), then
394–592 ms through the next turn. A second instrumented run separated that refresh: about 183–190 ms
for signatures/autocomplete and 189–194 ms filtering/sorting/derived rows; indexing was 0–3 ms.
Temporary phase instrumentation was removed after measurement. Logs from this session:
`/tmp/w40-tag-speed-baseline.log`, `/tmp/w40-tag-speed-large-baseline.log`,
`/tmp/w40-tag-speed-refresh-baseline.log` (temporary, not required to run the regression).

The fix prepares those derived values from immutable inputs off-main when paths are unchanged and the
library has at least 1,000 rows. Writes still verify and close their durable audit action before the library
row changes. The inspector reads that verified row directly. Publication rejects superseded library work;
a filter/sort change rejects only its older presentation, keeping the latest autocomplete cache.

The committed regression uses `SubjectEntryField.Coordinator`'s actual Return and end-editing (Tab) routes,
then waits two main-queue turns. First run: Return 115 ms, Tab 74 ms. Full-smoke run: Return 66 ms, Tab 86 ms. Final focused render-host recheck: Return 111 ms, Tab 73 ms.
The assertion is 250 ms at 50,001 rows, including the synchronous verified write, not a disk-only benchmark.
It also tests case spelling, undo grouping, file bytes, a newer filter and a replacement library.
These are synthetic Debug measurements, not a timing claim for every PDF or storage device.

model; cancellation/revision checks reject old snapshots; view revisions preserve newer filter/sort/flag
results; the existing collation cache is locked. The real write path, identity and verification guards,
and journal durability are unchanged. No migration is needed: this changes only rebuildable presentation.
