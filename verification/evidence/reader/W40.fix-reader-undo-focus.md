# W40.fix-reader-undo-focus — ⌘Z in a text field, and ⌘Z after launch

2026-11-05, Tart VM `archive-gui-runner`, generated scratch fixture (`AR-GUI-Fixture`), Reader Debug build.
Fixes suspect `S-001` and ledger row `R-21` (owner session reader-1, rows 32 and 37).

## The change

- `Views/TextUndoGuard.swift`: a local key-down monitor (no undo mid-IME composition or where `allowsUndo` is off), installed at launch. While an editable text view has the
  key window's keyboard (the field editor of any text field, a token field, a sheet's field), a bare ⌘Z undoes that
  text and is consumed, so Tags ▸ Undo Tag Change never sees it. Choosing Undo Tag Change from the menu with the
  mouse still undoes the tag change; ⌘Z with the list or a document pane focused still does.
- `ContextMenuTableView.viewDidMoveToWindow`: the list takes the keyboard once when its window opens, unless text is
  already being typed. Before, nothing had focus at launch and ⌘Z did nothing until the list was clicked.
- `AuditLedger.testLaunchID`: a DEBUG-only `-ARUITestLedgerID` lets a UI test keep its undo history across a
  relaunch (every UI-test launch otherwise gets a fresh scratch ledger).

focus at launch, so nothing else depended on launching without it.

A first version of the test compared raw xattr bytes after the undo and failed: the inverse write restores the
tags, not the exact plist bytes. It now compares the decoded tags.
