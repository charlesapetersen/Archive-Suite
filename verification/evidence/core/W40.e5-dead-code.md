# W40.e5 — dead-code scan (Periphery)

- **Date:** 2026-10-16. **Tool:** Periphery 3.8.0 (`brew install periphery`). **Runner:**
  `ops/verify/dead-code-scan.sh [reader|notes|processor|core]` (checkpoint 1, `3e43e94e`). Raw CSVs land in
  `$DEAD_OUT` (here `/tmp/w40e5-*.csv`; not kept, the script reproduces them).
- **How:** each app is built once with `build-for-testing`, so the index store holds the app and its unit tests
  (Reader, Notes) or its in-app headless drivers (Processor). Periphery reads that store. ArchiveCore is scanned
  against all three apps' stores at once, so a Core hit is a declaration no app and no app test uses.
- **No corpus material** is involved: this is static analysis plus the usual scratch-only test runs.

## Hits and what happened to them

### Kept, by reason

- **Part of a synthesized `Equatable`/`Hashable`.** Periphery does not count synthesized `==` as a read:
  `CorpusRootFingerprint`'s three fields, `JPEGPartnerIndex.FileSystemKey.bytes`, `Month.name`, `PageKey`,
  `SegmentationRow.pageCount`, `VoterGapVerdict.pNew`, Notes' `.task(id:)` keys and `NotesFolderNode.kind`.
- **Signature fixed by AppKit:** `@objc` actions and NotificationCenter selectors (`sender`, `note`), and the
  Reader's `sortDescriptorsDidChange` data-source callback.
- **Used where Periphery cannot see:** `ArchiveProcessor/scripts/*.swift` compile against ArchiveCore and keep
  copies of app types; they use `TagVocabulary.loadFailure`, `.count`, `.knownRoots()`, the 3-argument
  `MacOSTagger.applyTags`, and `ProbeOutcome.message`. Also launch arguments (`-APUITestInputDirectory`) and
  `NSPrincipalClass` (`LeakHarvestHold`).
- **Re-render triggers:** `@AppStorage`/`@ObservedObject` properties a view holds so that it redraws.
- **Formats and protocols:** decoded provider fields (`inputTokens`, `outputTokens`), SPEC fields
  (`labelNumber`), `CaptureReceiver.start`/`stop`.
- **Named elsewhere:** `CorpusWalker.scanDetached` (SUITE_TODO), `MovePlan.appending` (the finalize test seam's
  scenario label), `ItemSummary.created`/`modified` (dead, but removing them changes 15 test constructors; not
  worth the churn here).

## Found by the scan

- **`R-47` (new, `unreachable`):** the Reader guide and the SPEC promise that two same-facet date tags are
  flagged as ambiguous. `DocumentTags.sentWithIsAmbiguous` exists, but no app reads it, and no flag exists for
  two Years or two Months. A Daemon Report decision.
- **`R-25`, `N-48`** (already `unreachable`): the scan saw the same unwired code (`ReadStateCell`,
  `toggleReadState`, `clearReadState`; `RootFolderStore.setRoot`/`clear`). Kept for those decisions.
- **`S-016`:** clicking a column header in the Notes list probably does not sort it: the callback sits on the
  delegate, not the data source (the Reader fixed the same mistake).
- **`S-017`:** a pre-OCRed Processor run ignores the persisted document-segmentation review choice.
- **`S-018`:** the Processor tells the user it paces to the subscription window, but the OCR path never reads the
  reset time it parses.

## What Periphery missed (worth knowing when reading its output)

- Test-only types are not reported, because the tests reference them. Two app types live only through tests:
  Notes' `ThumbnailImageCache` (the app uses `InlineImageAttachment`'s cache) and `ZoteroCacheStore` (no app
  caller). Both are listed as live in `ArchiveNotes/CLAUDE.md`'s Implementation map: doc drift for `W40.b5`.
  Coverage (`W40.e4`) is the tool that finds these.
- The Reader's `DateCell` (ledger `R-26`, `unreachable`) was not flagged, though nothing outside its file uses it.
- Unused closure parameters are not reported.

## Verification

- ArchiveCore `swift test`: green (XCTest and 110 Swift Testing).
- Reader unit bundle: 422 tests, 3 skipped, 0 failures (`DeepLinkTests` skipped as usual).
- Notes unit bundle (`ArchiveNotesUnit`): 219 XCTest + 984 Swift Testing, 0 failures.
- Processor: clean `build-for-testing`, no warnings; all 27 headless drivers that need no key or money (the W40.e1
  list) exit 0.
- Release builds of all three apps, to catch a `#if DEBUG`-only use; no new compile warnings in any app.
- Tier-2: the Processor diff touches `Capture/` and `Net/`, so an adversarial reviewer tried to refute "deletes
  only unread code, changes no behaviour" hunk by hunk: persisted shapes and synthesized equality, side effects in
  removed arguments, protocol and overload traps, the Drive OAuth scope and requests, live-capture OCR requests
  (which pass literal `nil` for previous text and image, so the two removed config fields were never read there),
  and the scripts that compile app sources on their own. No blockers. One stale comment it found was fixed
  (`FileRelayReceiver.swift`: `DriveObjectStore` lists with `files.list`, not `changes.list`).
