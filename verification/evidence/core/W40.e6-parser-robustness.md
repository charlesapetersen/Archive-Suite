## Bugs found

**Fixed here (each with the test that failed before it):**

1. **Tag facets took signs and long zero runs** (ArchiveCore `DocumentTags.parseMonth`/`parseDay`/`parseDecade`).
   `Int(_:)` accepts `+`, `-` and any number of leading zeros, so `-170s` was a decade starting in -170,
   `+00s` one starting in 0, and `+12 December`, `0007 July`, `Day 013` filled their facets. A facet edit removes
   the token it consumed, so a lookalike subject was one edit away from deletion. Now ASCII digits only: month and
   day 1–2 digits (`3 March`, `03 March`, `Day 5`, `Day 05` still read), decade 3–4. SPEC wording tightened to say
   so. Test: `testSignedAndOverPaddedNumbersStaySubjects` plus the fuzz property. Tier-2 review (opus): no caller
   or writer depends on the old leniency (the Processor normalises LLM days through `dayNumber` before writing;
   Notes builds decades from unsigned years; Android sends months as ints); the corpus index holds only canonical
   `NN Month` and unpadded `Day 18`–`Day 31`.
2. **A note with an unclosed block header grew by one block per save**, through BOTH save paths: the store
   (`BlockParser.serialize`) and the editor (`MarkdownBridge` writes a header per chip). This was already filed
   as `W40.fix-notes-unclosed-header` by W40.c1. Its required test, the nine-line rehearsal note encoded three
   times and byte-identical each time, now passes, so that item closes with this commit. The fix keeps the §6
   rule that such a header becomes a freeform block (`BlockHeaderTests.malformedHeaderDegradesToFreeform`, which
   an earlier version of this fix broke and which stays as it was). `Block.headerless` (carried as
   `SourceAnchorBox.headerless` through the editor) writes that block back with no header of its own. Tests:
   `unterminatedBlockHeaderIsWrittenBackAsItWas`, `unterminatedBlockHeaderSurvivesTheEditor`,
   `rehearsalStoreUnclosedHeaderNoteIsStableAcrossThreeSaves`, and the damaged-file loop, which went from 262
   unstable saves to 0. Tier-2 review (opus): no data-loss regression; the flag is set in one place and worked out
   again from the text on every editor save; `Block ==` now compares it. Two older concerns it raised are
   `S-019` and `S-020`.

**Filed (reproduced; each carried as a known issue, so the suite stays green and the fix session sees it flip):**

- `W40.fix-core-classification-from-body` (S3). `PDFHeaderParser.parseClassification` takes the first
  `Classification:` line anywhere on the page. A page-2 header without one borrows a body line such as an OCR'd
  `Classification: Top Secret` marking, and a file name starting with the word beats the real header line.
  Carried by `testClassificationIsReadOnlyFromTheHeaderKnownIssue` (strict `XCTExpectFailure`).
- `W40.fix-notes-block-marker-in-text` (S4). A line of note text that reads as a block header
  (`<!-- block: freeform -->`) is taken as one on the next read. The line disappears from the text and the block
  splits in two. The format has no escape. Carried by `blockHeaderLineInTextKnownIssue` (`withKnownIssue`).
- `W40.fix-processor-relay-parse-lenient` (S4), three cases, all printed as `KNOWN` by the relay fuzz:
  (a) `JSONSerialization` drops a leading U+FEFF from every key and value, even an escaped `\ufeff`
  (`JSONDecoder` keeps it; Mac and iOS both affected), so such a value reads back changed and the receiver's
  recomputed fingerprint differs; (b) a JSON `true` reads as `"1"` (it arrives as an `NSNumber`); (c)
  `identityFromName` reads `g__007.jpg`, `g__+7.jpg` as `(g, 7)`, and the receiver's cleanup
  (`FileRelayReceiver.swift:305`) deletes a name by the identity it reads. No writer emits any of these, so the
  impact today is nil.

**Clean:** the sent-with wire date (anything accepted re-spells byte for byte), quality tokens, the write-then-read
round trip through xattrs, the page-2 body strip (always a trailing run of the page's lines), damaged PDFs, the
relay encoders and fingerprints, deep JSON nesting, cross-platform relay bytes, and the staging manifest (every
damaged body either resumed the identical record or was quarantined byte-for-byte with recovery blocked).
