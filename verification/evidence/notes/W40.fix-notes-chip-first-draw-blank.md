## Why

A DEBUG timeline (not committed) logged each chip's fragment state, provider count, view and parent at each
point after a note switch. Two switches gave the same sequence (times in ms after the load):

```
2102 didMoveToWindow   provider 0, view -
2113 layout            fragment laid out, provider 0   (after layoutViewport() + the stranded install)
2120 viewWillDraw      provider 0                      ← the first frame draws the body without the chip
2124 pass1             provider 1, view loaded, no parent
2187 layout            view rehosted in EditorTextView by the stranded check
2199 viewWillDraw      view in _NSTextViewportElementView, layer attached  ← the chip appears
```

So TextKit creates the provider while it draws the fragment. Drawing the chip fragments once into a 1×1 bitmap
during the first layout creates it early. With the fix, the timeline reads `layout: provider 1, view in
EditorTextView` and then, at the first `viewWillDraw`, `view in _NSTextViewportElementView, layer attached`.
The chip is in place on the first frame.
