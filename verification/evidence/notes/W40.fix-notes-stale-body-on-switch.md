## Reproduction

The inspector/body identity mismatch was already addressed by
`W40.fix-notes-inspector-jitter`: the old note remains visible whole until the incoming
body loads. This item checks whether that old editor can still accept input.

Source inspection found `.disabled` on the SwiftUI representable but no bridge to
`NSTextView.isEditable`; `EditorTextView.commonInit` always enabled editing. Custom
image paste wrote its asset before inserting the attachment.

An initial regression held the incoming note's load with a DEBUG-only continuation,
clicked the old text, attempted real typing, and invoked the production image-paste
handler through the existing test seam. On baseline, ordinary click-and-type did not
insert its marker. The image handler did accept its PNG: after the switch flushed,
the outgoing note grew from **265 to 302 bytes**; the incoming file stayed unchanged.
Thus the measured baseline write is the image-paste path, not a claim that a normal
click focused the disabled editor. Result: one failing test at the outgoing-file
byte comparison. Raw result: `/tmp/notes-stale-body-before2/notes/uitest.xcresult`.

## Change and safety review

`MarkdownEditorView` now reads SwiftUI's `isEnabled` environment on creation and
updates, assigning it to the actual text view's `isEditable`. Input, custom list
commands, source/passage/image paste and formatting all refuse a disabled editor;
image/source paste checks before reserving or writing assets. AppKit menu validation
also refuses disabled text commands. A VM check established that SwiftUI's Undo menu
bypasses those validators. Each editor now owns a stable undo manager that gates
both availability and execution (including nested undo), preserving its history
when a selection load is cancelled. Explicit `undo:`/`redo:` responder actions
route the standard Edit commands to that manager rather than the window's history.

Serialization is deliberately still allowed while disabled: keystrokes accepted
before selection changed must flush to the outgoing note. The existing loaded-ID
and generation checks still reject serialization from retired editors.

Independent adversarial review found no remaining code defect. It identified the
Undo/Redo validation route for verification, and a test-oracle weakness where Undo
followed by Redo could cancel itself; validation gates and separate per-command
assertions close those cases.
