## What is real here

Every other Notes UITest talks to an in-process Zotero stub (`ZoteroUITestTransport`) and records the links it
would open (`WorkspaceOpenSpy`). This journey replaces both:

| Piece | How |
|---|---|
| Zotero | Zotero **10.0.6** from zotero.org, at `~/Applications/Zotero.app` in the guest. `ArchiveNotes/scripts/vm-zotero.sh start` gives it a profile with the local API switched on (`extensions.zotero.httpServer.localAPI.enabled`), launches it, and seeds one book through `/connector/saveItems`: *Notes on the Analytical Engine (W40.d10 seed)*, Ada Lovelace, 1843. No account, no Better BibTeX. |
| Notes ↔ Zotero | the production `ZoteroClient` over `URLSession` to 127.0.0.1:23119, citation style `apa` |
| Reader | the Debug Reader built at the same commit in the guest, registered with `lsregister -f`, launched by the test on `reader-corpus/` (`-ARUITestRootPath`) |
| Links out of Notes | `-ANUITestRealWorkspaceOpen YES` (new, DEBUG only) turns the recorder off, so `openExternalURL` calls `NSWorkspace.open` |
| Links into Notes | `NSWorkspace.shared.open(url)` from the test with **no application named**, so Launch Services picks the app by the `archivenotes:` scheme, as for a link clicked in Scrivener |

The guest's Launch Services database had exactly one claimant for each scheme
(`dd-reader/…/ArchiveReader.app` for `archivereader:`, `dd-notes/…/ArchiveNotes.app` for `archivenotes:`).

### Finding 1 — Auto-fill from the real Zotero crashes Notes (`W40.fix-notes-zotero-csljson-crash`, S2)

The crash report (guest `~/Library/Logs/DiagnosticReports/ArchiveNotes-2026-10-15-175727.ips`, run 1):

```
EXC_CRASH (SIGABRT) — abort() called
objc_exception_throw
+[NSJSONSerialization dataWithJSONObject:options:error:]
ZoteroClient.fetchCSLviaLocalAPI(_:)
ZoteroClient.fetchCSL(_:)
```

The cause is the shape of Zotero's answer. `GET /api/users/0/items/5SXHDTMB?include=csljson` returned (other keys
trimmed):

```json
{"key": "5SXHDTMB", "csljson": "[\n\t{\n\t\t\"id\": \"http://zotero.org/users/local/JeE49aLm/items/5SXHDTMB\",\n\t\t\"type\": \"book\",\n\t\t\"publisher\": \"Richard and John E. Taylor\",\n\t\t\"publisher-place\": \"London\",\n\t\t\"title\": \"Notes on the Analytical Engine (W40.d10 seed)\",\n\t\t\"author\": [\n\t\t\t{\n\t\t\t\t\"family\": \"Lovelace\",\n\t\t\t\t\"given\": \"Ada\"\n\t\t\t}\n\t\t],\n\t\t\"issued\": {\n\t\t\t\"date-parts\": [\n\t\t\t\t[\n\t\t\t\t\t\"1843\"\n\t\t\t\t]\n\t\t\t]\n\t\t}\n\t}\n]"}
```

`csljson` is a **string** holding a JSON **array**. `fetchCSLviaLocalAPI` expects an object and passes the value
to `JSONSerialization.data(withJSONObject:)`, which raises on a string. The stub and the unit tests both return an
object, so nothing caught it. The date parts are strings too (`"1843"`), and `CSLDate.dateParts` is `[[Int]]?`.

The citation path is not affected: `include=bib` returns HTML under `bib`, and that path works (step 1).

## Measured along the way

- Zotero keeps answering the old style ID `chicago-note-bibliography` (Notes' default) although its bundled file
  is now `chicago-notes-bibliography.csl`. An unknown style gets HTTP 400 ("Invalid style"), which Notes shows as
  "Citation unavailable".
- Reader lists only files with a `Read` or `Unread` tag. Untagged, the scratch corpus showed "No tagged
  documents — Scanned 10 files". This is by design (`SPEC/tag-format.md`), not a finding.
- XCUITest querying Zotero's own accessibility tree timed out after about two minutes, so the journey reads
  Zotero's selection from a screenshot rather than a query.

## Not covered here

- A link arriving while Notes is **not running** (the "waits for the index at launch" promise). Launch Services
  would start Notes without the harness arguments, on the VM's default store instead of the fixture.
- Reveal with **Reader not running**. The same problem: Reader's root would come from its stored grant, not the
  fixture.
- `#block-n` scrolling, the clipboard Zotero banner, and Zotero not running. The stub tests cover those.
- The chip buttons themselves. Reveal goes through the same closure via a DEBUG seam, as in G6, because XCUITest
  cannot hit-test TextKit attachment subviews.
- Scrivener accepting `archivenotes://` (owner, §17).
