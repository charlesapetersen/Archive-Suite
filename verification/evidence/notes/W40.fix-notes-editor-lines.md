# W40.fix-notes-editor-lines — Return, Backspace and Bulleted List in the styled editor

2026-11-05, unattended. Unit bundle on the host (app-hosted, draws nothing), UI tests in the Tart VM
(`ops/gui/vm-gui-runner.sh notes xcuitest`), the scratch fixture store only. From owner session notes-1
([`../../sessions/notes-1-returned.md`](../../sessions/notes-1-returned.md) rows 8 and 10; ledger N-12).

## What was wrong, measured

1. **Return and Backspace on the empty last line did nothing.** On unmodified main, `EditorLinesTests`' Return test
   stopped at the second Return with
   `NSRangeException: *** -[NSConcreteTextStorage attribute:atIndex:effectiveRange:]: Range or index out of bounds`.
   `insertNewline`, `deleteBackward`, Tab/Shift-Tab and the block toggles read the paragraph's kind at
   `storage.length` on that line, and AppKit swallows an exception raised in a key or menu action. So the second
   Return, a Backspace there, and Bulleted List on a fresh line all did nothing. Typing anything else first
   made it go away. That is why it seemed to come and go.
2. **The save did not match the screen, so a reselect changed the lines.** The serializer wrote every newline in
   plain text as a paragraph break and dropped empty pieces. One Return reopened as a blank line. Three reopened
   as one. A blank line deleted with Backspace came back.
3. **Lists showed no marker.** A list item is stored as its text plus `BlockKind.listItem`. Nothing drew a bullet
   or number, so Bulleted List moved the line 4 points.

## The fix

- `EditorFormatting.blockKind(at:in:)` reads the typing attributes on the empty last line. A block toggle with
  no selection sets the typing attributes too.
- `MarkdownBridge.plainLines` writes a run of newlines between two lines by its count:
  - one is a hard break (`\` at the end of the line);
  - two is a paragraph break;
  - each one past two is a hard break that starts the next paragraph.

  Apple's parser reads each of these back as that many newlines, checked with `AttributedString(markdown:)`.
  Next to raw HTML the break stays a paragraph break. A line starting with `-`, `=` or `<` is escaped, because
  after a hard break it would underline the line above as a heading or start an HTML block.
- Blocks of different kinds (heading, list, quote, code) are one newline apart on screen, which is what a Return
  there makes. The file still has a blank line between them. Return at the end of a heading starts a text line.
  Backspace that joins a line to the one above gives it that line's kind. Block-kind changes can be undone, and
  they save.
- `ListMarkers` and `EditorTextView.drawListMarkers` draw •/◦/▪ and numbers in the list indent, including on
  an empty last line.

**Paths not taken, and why.** Context menu: the editor adds no items to AppKit's default text menu, which has no list or line commands. Drag:
it moves text, not line breaks. The Extracts window: it uses the same `EditorTextView` and `FormattingContext`,
and differs only in the window around it. Raw mode: it is a plain `NSTextView` of the Markdown, which has none
of these overrides.
