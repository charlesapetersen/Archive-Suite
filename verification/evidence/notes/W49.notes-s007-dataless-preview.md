# W49.notes-s007-reproduce — the source-block preview downloads a cloud placeholder

Suspect `S-007` (`verification/SUSPECTS.md`), 2026-11-20. Reproduced.

## The placeholder

No scratch placeholder had to be made: the owner's OneDrive (`~/Library/CloudStorage/OneDrive-Stanford`, a
File Provider domain) already holds dataless PDFs. One non-sensitive 6.2 MB PDF was used
(`Personal/Outdoors/Epicurean-Backpacker-JJF-082515.pdf`). `ls -lO` showed `compressed,dataless`. Nothing in the
corpus was touched.

## The probe

`W49.notes-s007-probe.swift` makes the same two calls as `ReaderPreviewPopover.showPDF`
(`PDFDocument(url:)`, then `page(at:)`). It runs them either bare, as the popover does, or inside the guard
`CorpusWalker.withDatalessMaterializationDisabled` sets (thread-scope `IOPOL_MATERIALIZE_DATALESS_FILES_OFF`). It
checks `SF_DATALESS` with `stat(2)` before and after.

One trap: the engine starts its sessions with the process-scope policy already **off** (read back as `1` in
this session). So without the probe's own `setiopolicy_np(…PROCESS…, ON)`, even a plain `read(2)` failed with
`EDEADLK` and both modes looked safe. A Notes launched from Finder runs with the default policy, which downloads.
A test run under the engine therefore cannot show this bug unless it sets the policy itself.

## Result

```
set process ON: 0 now: 2
before: dataless=true
mode=guarded doc=false pages=-1 page0=false secs=0.02
after: dataless=true
set process ON: 0 now: 2
before: dataless=true
mode=unguarded (popover) doc=true pages=54 page0=true secs=1.90
after: dataless=false
```

The bare call downloaded the whole file (54 pages, 1.9 s) and left it materialised. With the guard on, the file
stayed a placeholder and `PDFDocument(url:)` returned nil, so a guarded popover would reach its
"Could not open PDF." branch. The fix has to word that case itself.

Afterwards `FileManager.evictUbiquitousItem(at:)` made the file a placeholder again (`compressed,dataless`).

## The fix (W49.notes-s007-fix)

`PreviewCloudFile.opening` stats the file and, when it is not dataless, opens it inside the thread guard; a
placeholder gets "This PDF is in the cloud and has not been downloaded to this Mac." and a "Download and Show"
button, whose `PreviewCloudFile.download` reads the first byte with the thread policy on. `W49.notes-s007-fix-probe.swift`
compiles the shipped `PreviewCloudFile.swift` (with a copy of the guard standing in for ArchiveCore) and runs the
preview's path, then the button's, on the same placeholder, with the process policy set back to on:

```
set process ON: 0
before: dataless=true
opening=inCloud
secs=0.00 after opening: dataless=true
download (Download and Show) -> true secs=2.92
re-opening=show pages=54
after evict: dataless=true
```

The preview downloads nothing; the button downloads and shows the file. The probe evicts it again at the end.
