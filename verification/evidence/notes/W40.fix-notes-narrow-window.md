# W40.fix-notes-narrow-window — minimum-width panes

2026-10-25. Baseline `8318b683`; final code and tests are in this commit. All GUI runs used the headless
Tart VM at 1920×1200 and the generated AN-GUI-Fixture store. No host windows or real-store/corpus writes.

## Reproduction

Removed `LayoutGuardUITests.narrowWindow` without changing production code, then ran:

```sh
ONLY_TESTING=ArchiveNotesUITests/LayoutGuardUITests/testMainScreensLayOutInLightMode \
  ART_DIR=/tmp/w40-notes-narrow-before bash ops/gui/vm-gui-runner.sh notes xcuitest
```

One test failed with two failures (one per window). Both Notes and Extracts were 1121×612 at typical
size with zero violations, then shrank to 1053×612 with six violations on open and settled:

```text
scrollView: frame (395,316 220×530) leaves window (429,264 1053×612)
an.sidebar.newFolder: (405,860 11×11)
an.locations.remove.f1f1f1f1-0000-0000-0000-0000000000f1: (1495,374 10×10)
an.detail.metadataScroll: (1156,392 360×242)
an.editor.rawToggle: (1495,671 11×14)
editor scrollView: (1156,693 360×125)
```

[Before: clipped sidebar and inspector](W40.fix-notes-narrow-window-before.png).
Raw log/result bundle: `/tmp/w40-notes-narrow-before/notes/`.

An explicit `.windowResizability(.contentMinSize)` on both scenes reproduced the same 1053 pt minimum
and all six violations, plus the three new reachability assertions per window. That change was removed.
Diagnostic log: `/tmp/w40-notes-narrow-policy/notes/xcuitest.log`.

## Change

The rendered list occupies 527 pt (1121 minus 220 sidebar, 360 detail and two 7 pt dividers), while
its implicit minimum allowed less. `NotesBrowserView` now reserves 540 pt for the list. The window's
minimum still derives from that floor plus the current visible side panes. Neither whole-window width
nor either side pane is fixed to a new constant. The layout guard's known-failure exemption and the
visual tour's unreachable-Add-Folder exemption are removed.
