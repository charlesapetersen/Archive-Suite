# Independent check of five ArchiveNotes reproductions

Codex (gpt-6.2-sol), 2026-11-21, at baseline `b0539267`. The first reproductions were run by Opus 5.5 in
`57565daa` and recorded in `98d96844`. The independent checks used the generated Notes VM fixture or
fresh temporary stores. The existing `ArchiveNotesTests/NotesSmallSuspectTests` remain the regression
tests for the five follow-up items.

## S-010 · Remove 2 Items from Reading

In the Notes window, select Reading and press ⌘N to create a second sole-instance note alongside
My First Note. Verify in the scratch library's `organization.json` that each note is filed only in
Reading. Command-click to select both notes, right-click a selected row, and choose **Remove 2 Items
from “Reading”**. The alert asked **Delete “My First Note”?** while the window still showed two selected
items. After **Delete Note**, only the named note was in the library's `Trash/` folder. Untitled stayed in
`items/` and retained its Reading membership. No second alert appeared. The VM test checked the alert
title against the note that moved to Trash, since the selection order can change which note is named.
The retained `s010MultiRemove` test also covers a replicant alongside the two sole instances. The fix
must keep a fresh membership check at confirmation and preserve the existing recoverable Trash path.

## S-016 · Title column clicks change the arrow and leave the rows in place

In **All Notes**, the fixture list initially read Moore on Intel culture, Lovelace paper, My First Note.
Click **Title** twice. The screenshots showed the Title arrow pointing up after the first click and down
after the second. The row order stayed the same both times. `NotesTableView.Coordinator` defines
`tableView(_:sortDescriptorsDidChange:)`, but the table's `NotesTableDataSource` receives AppKit's
data-source callback. The fix should retain `s016HeaderSort`'s row-order assertion and update its
assertions about the callback's wiring to match the fix.

## S-011 · The row command creates from the saved template body

In a fresh scratch library, save “First field survey” as the template body and register a pending
“Second field survey” save with the editor's flush registry. Dispatch **New from Template ▸ Field Notes**
from the real row menu through AppKit. Reading the new note from disk showed the first survey, and the
registered flusher received zero calls. Standard New through `NewItemFlow.create` called the flusher
once and created a note containing the second survey.

Then make only the scratch template directory read-only and attempt to save “Third field survey”.
After the save failed, restore directory permissions and keep the same model with its failed-save
flag. Standard New refused creation. The row command made a note from the second survey, the last
body saved to disk. This exercised the actual menu action with a deterministic pending flush and a
real storage error. The two `s011RowMenuSkips…` tests cover the editor debounce and failed-save cases.

## S-014 · The source still exists after an archive folder rename

The screen-free check went through `ReaderRootChooser.chooseRoot` with a scratch folder returned by
the picker seam and a private bookmark defaults suite. The exact preview path initially resolved
`survey.pdf`. After renaming its folder and releasing the prior preview scope, the same resolver
entered basename search at the old path and returned `.notFound`. A fresh root store using the same
bookmark resolved the PDF at the renamed path. `ReaderPreviewPopover.present` maps that outcome to
“Source file not found in the archive.” Owner call 29 asks Notes to offer the folder chooser or report
that the search could not finish when the root moved or was renamed in session. The fix should keep
`s014MovedRoot` and update the old `.notFound` assertions for this case, including the one in
`DurableLinkE2ETests`.

In the VM, use **File ▸ Choose Archive Folder…** with the existing picker seam pointed at the generated
archive. Open the Reader-backed note's source preview and confirm it shows `sample.pdf`. Dismiss the
preview, rename the generated archive folder, verify the PDF still exists there, and reopen that same
source preview. It displayed **Source file not found in the archive.** The chooser button was absent.

## S-012 · An exact lowercase tag can hide a note with that tag

Use **Edit Tags** in a note's row menu to enter `fieldwork` and verify that the saved Markdown
contains `Fieldwork`. Submit the complete lowercase string in **Filter by tag…** with the paste
command and Return. The filter chip read `fieldwork`, and the note disappeared. Clear the filters
and submit `Fieldwork` the same way. The chip read `Fieldwork`, and the note was visible.

The first VM probe sent sequential keystrokes and did not observe a miss. It did not verify the
submitted spelling. The controlled probe checked both chips explicitly. This confirms the failure
when the full lowercase token reaches the filter, including paste. Prefix completion can supply the
stored capitalisation. The fix keeps `s012TagFilterCase` as its regression.
