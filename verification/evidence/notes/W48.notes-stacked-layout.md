## What the runs found, and the fixes made in the same item

1. **Run 1** (`StackedLayoutUITests` + the stacked light layout sweep): in the VM's 612 pt window the stacked note
   pane got 313 pt and its editor **9 pt**; the list kept its full remembered height and the window did not grow.
   The divider reading order did not find the table (the test looked for the wrong identifier).
   Fix: the panes' height is measured; the list is drawn, and its divider clamps, within what leaves the note its
   floor, never below 140 pt; the stacked minimum height is the two floors.
2. **Run 2**: the window now grows to the stacked minimum (612 → 639 pt), but an extract's editor got 103 pt
   against 110 pt for its details at a 440 pt note floor. Floor raised to 480 pt (minimum 627 pt; window 679 pt).
   The stacked audit found two issues the side-by-side audit never reached, because the narrower side-by-side list
   keeps those columns off screen: the Quality cell's unnamed hosting group, and the filter bar's decorative date
   dash measured as 1.25:1 text. Fixed: the group is labelled Quality; the dash is hidden from accessibility.
3. **Run 3** (the stacked tests and every `LayoutGuardUITests` and `AccessibilityAuditUITests` test): all
   side-by-side audits and sweeps pass; the divider drag, clamp and relaunch pass (list 330 pt at the bottom of
   the drag in an 869 pt window); reading order is table, divider, editor; Tab reaches the editor from the list in
   18 presses stacked and 22 side by side. Left: an extract's empty Tags cell had no description (empty Tags and
   Sources cells now read "No tags" / "No sources"), and the narrow-and-tall sweep could not grow a window that
   reached past the screen bottom (it now moves the window up first).
4. **Run 4**: the stacked audits light and dark, the stacked sweeps (narrow and tall 767×679 → 767×878), the switch
   test and `WritingJourneyStackedUITests` (all 7 journey tests stacked): **12 of 12 passed**.

The switch test: four switches, each with a line typed inside the autosave delay just before it. The text stayed in
the editor and reached disk each time, and the row stayed selected. The editor's scroll bar stayed near the end:
run 4 measured 1.0 → 0.91, 1.0 → 0.93, 1.0 → 0.90, 1.0 → 0.99 (the text reflows to the new width). The Extracts
window followed both switches with its extract still open.

5. **Stacked visual tours** (`VISUAL_REVIEW=1`): at the window's minimum the list's filter bar (three rows when
   narrow) spilled up under the toolbar over its Clear button at a 140 pt list; the UITest status probes showed
   through the note pane, which had no background of its own. Fixed: list floor 220 pt and clipped; the detail pane
   has the window background. The next tour **crashed the app** on the folder tree's animated toggle, in AppKit's
   layout pass: the panes' measured height was written to state and fed the list's frame. Fixed with
   `StackedPanesLayout`, which cuts the list while placing it.
6. **Run 6** (checkpoint 9; the stacked tests, sweeps, audits and the stacked journey, 14 tests): 13 passed, no
   crash, the tree toggles four times stacked. Failed: on the first switch to stacked the editor's scroll fell
   from 1.0 to 0.45. Open; see `execution-plans/items/W48.notes-stacked-layout.md`.
