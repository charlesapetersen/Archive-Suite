# W40.fix-notes-row-clip — Notes list rows clipped to about half their height

- **Date:** 2026-10-21 · **Configuration:** Debug, ad-hoc signed in the guest
- **Environment:** Tart VM `archive-gui-runner`, headless, XCUITest; GUI fixture from `scripts/make-notes-fixture.sh`
- **Command:** `ONLY_TESTING="ArchiveNotesUITests/LayoutGuardSelfTests,ArchiveNotesUITests/LayoutGuardUITests"
  ops/gui/vm-gui-runner.sh notes xcuitest`

## Before

Reproduced by `W40.e9` on 2026-10-11 (`W40.e9-layout-guard.md`): every list cell's text was 12 pt tall for a
13 pt font whose line needs 16, the rows 16 pt with 14 pt cells. Screenshot:
[`W40.e9-row-clip-extracts-dark.jpg`](W40.e9-row-clip-extracts-dark.jpg). The sweep carried it as a strict
`KnownIssue` (`$0.kind == .short && identifier.hasPrefix("an.cell.")`), 7 in the note window and 2 in Extracts.

## Cause

`NotesTableView` set `rowHeight` and then `usesAutomaticRowHeights = true`, so the rows took their height from
the cells' fitting sizes. The text fields' vertical compression resistance (750) lost to that, and the rows
collapsed below the text. Reader's table shares the setting but makes its name field's vertical compression
resistance required, because its rows do grow (a search snippet adds a second line). Every Notes cell is one
line, so the fix is a fixed row height: `ceil(max(20, 13 × 1.8))` = 24 pt, no automatic heights.

## After — 3 tests, 0 failures, with the KnownIssue deleted

The row-clip entry is gone from `LayoutGuardUITests`, so any short cell text now fails the sweep. Its
remaining reports are all `W40.fix-notes-narrow-window` (still open). From the Extracts window, dark, minimum
size, settled: `cell (662,442 300×24)` holding `text#an.cell.title.44444444-… "On egalitarian culture" (663,445 298×18)`.
The populated row is now the same height as the empty stripe rows below it:
[`W40.fix-notes-row-clip-after-extracts-dark.jpg`](W40.fix-notes-row-clip-after-extracts-dark.jpg).
