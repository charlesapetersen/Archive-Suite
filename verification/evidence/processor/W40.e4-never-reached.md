# Archive Processor: triage of 508 functions no run executed

Paths are relative to `ArchiveProcessor/macOS/Sources/ArchiveProcessor/`. The per-function table is the `.tsv` beside this file (columns `file line function class group tested-by`).

Method: the union is 20 runs: ArchiveCore's unit tests, the Processor's 55 key-free drivers, the Processor UI tests in the VM in three runs (two chunks of the whole bundle, then chunks 3 and 4 in one guest), and the Reader and Notes runs. A function is listed when none of the 20 executed it. For each, `rg -nw -t swift <base name>` over `ArchiveProcessor/macOS/Sources` and `packages/`, and separately over `ArchiveProcessor/macOS/Tests`; generic names, closures and sheet triggers were followed by hand (`Views/OCRView.swift:600-700` lists every sheet and its trigger). The key-free drivers live inside `Sources`, so a caller in a `*TestDriver.swift` file is a test, not a user path. "tested-by" (view rows only; `-` elsewhere) says which UI test is written to reach the row, from matching accessibility identifiers and labels against `ArchiveProcessorUITests`; it is a reading of the tests, not a trace, and `[gated: …]` marks a test that skips unless its variable or flag file is set.

**Caveats that change the reading.** The gated journeys (`PROCESSOR_JOURNEY=reviews`, `livecapture`, `bulkocr`, and the others) and `VisualReviewUITests` (flag file) were skipped, so their rows stay listed. Seven drivers failed partway on known main defects (batch-resume, collection-organize, segmentation-chooser, entity-feature, run-quit-resume, settings-solver, tagging-failure). Under coverage, 4 `ProcessorUITests` failed in the last run (`testInstitutionalComputingImportOffersNeutralFolderChooser`, `testLocalAgentSettingsAndFilesShowAPIKeyCost`, `testLocalAgentSettingsAndFilesShowSubscriptionCostAndGuidedSetup`, `testMultiPageScratchPDFDisablesTaggingAndExplainsAutoReOCR`), and earlier chunks lost the four `AccessibilityAuditUITests`, `testBackfillWritesOnlyTheAcceptedFolder` and `testCollectionInterviewWaitsForPickerIntake`. A function after a failure point can show as never run for that reason alone; the groups where that plausibly applies say so in their heading ("† failure"). The four accessibility audits tour many screens, so any view group may owe some rows to them.
