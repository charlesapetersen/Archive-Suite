## How it runs

`ArchiveProcessor/scripts/journey-bulk-ocr.sh` → `PROCESSOR_JOURNEY=bulkocr ops/gui/vm-gui-runner.sh processor
xcuitest`: the runner copies the box from the read-only rehearsal share onto the guest disk with `ditto`, hands the
key in through `tart exec -i` stdin to a 0600 file, and runs `BulkOCRJourneyUITests`, which only launches the app
with `ProcessFilesTestDriver`'s environment and waits for its marker. The driver runs the real Process Files
pipeline (`OCRProcessor.startProcessing`) with the shipped defaults where a headless run allows them: segmentation
approach Manual (the default: the OCR call classifies each page), merging off (one image, one two-page PDF), rotation
off, Automatic tagging, segment JSON on, no collection segmentation. Its auto-pilot accepts each review as proposed.
The runner deletes the key file, records the guest's own hex reading of every PDF's tag xattr, and brings the run
back with `ditto`. `scripts/journey_bulk_ocr_check.py` then checks every PDF (below).

The cost is stated first, by the app's own estimator with the inputs the Cost Estimate box uses (`estimate.txt`),
and a run estimated over the cap is refused. Every request passes through a meter on `NetworkSession`'s seam that
reads the reply's `usage`, refuses to send unless what is spent plus every request in flight (each priced at the
dearest call so far) stays inside the cap, stops after a reply it cannot price, and writes `spend.tsv`.

## The $0 runs (2026-11-18)

**Apple Vision, 6 photos, No tagging.** Every page failed inside the app: `Apple Vision could not read this image:
… Foundation._GenericObjCError error 0`, error code `vision_request_failed`. The same `VNRecognizeTextRequest` on
the host read the same photo (24 lines), so it is the guest, as `ArchiveProcessor/KNOWN_ISSUES.md` already records.
The six PDFs it wrote for the failures passed `qpdf --check` and `pdfcpu validate` and carried the page-2 header
(`Extracted text.` / `00001 — RG 165.jpg` / `Apple Vision · macOS Vision · 18 November 2026` / `No text returned by
model.` and the error).

**The gateway route against a stand-in (`scripts/fake_gateway.py` in the guest), the whole box.** The stand-in
answers in the app's own reply formats with a fixed cycle of classifications, so **the split and the tags' content
mean nothing here**; what the run shows is the route and the output. It refuses any request without the key the
journey handed over.
