## Anthropic and Mistral: Process Files in the VM

`cd ArchiveProcessor && ./scripts/journey-bulk-ocr.sh --route anthropic|mistral --paid --max 3`: the W40.d1 journey
(`BulkOCRJourneyUITests` → `ProcessFilesTestDriver` → `OCRProcessor.startProcessing`) with the provider's direct
client, its Keychain key handed to the guest as a 0600 file and deleted after, No tagging. The checker
(`scripts/journey_bulk_ocr_check.py`) ran `qpdf --check` and `pdfcpu validate` on every PDF, read page 2 against
SPEC/tag-format.md and decoded the tag xattrs.

Page 2 of each PDF carries the text. Anthropic, `00001`: "RG 165 RECORDS OF THE WAR / DEPARTMENT GENERAL AND /
SPECIAL STAFFS"; `00002`: "W.D. - Committee on Education + Special Training"; `00003`: "August 20, 1918. /

General."), which is why it classified that photo Document Start rather than Folder. That is a reading of the page,
not a fault in the client.

guest"; W40.d1 saw it on all six photos), and the app cannot run on the host's screen unattended. So the shipped
`VisionClient` (the reader `PageReaders.reader` picks for Apple Vision) was compiled into the headless host and given
