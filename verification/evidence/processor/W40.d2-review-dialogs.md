- **Status:** done 2026-11-19. Every review dialog a Process Files run opens was answered by hand, with choices that
  differ from what was proposed, and the output read back. The tags, the removals, the rotation and the typed manual
  tags carry the choices. Two defects reproduced and filed: the per-page review's keys do nothing
  (`W40.fix-processor-review-keys`, S3), and page 2's `Classification:` keeps the proposal, not the choice
  (`W40.fix-processor-review-classification-stale`, S3, Tier-2). A third, cosmetic: the Interrupted Run box names
  the stored provider for a Local Agent run (`W40.fix-processor-pending-run-caption`, S4). Ledger rows P-23, P-25,
  P-32, P-35, P-37, P-38 and P-40 moved on it.
- **Material:** the first six photos of RG 165 — War Department (the W40.c1 rehearsal copy,
  `verification/rehearsal.md`): a box label, a folder photographed sideways, and four typed War Department pages.
- **Build:** Debug, in the Tart GUI VM (`archive-gui-runner`, macOS 27.2 guest, ad-hoc signed), at the commit that adds
  this file. Nothing ran on the host's screen. $0: no key and no network call.

## How it runs

`ArchiveProcessor/scripts/journey-review-dialogs.sh` → `PROCESSOR_JOURNEY=reviews ops/gui/vm-gui-runner.sh processor
xcuitest`. The runner copies the six photos from the read-only rehearsal share onto the guest disk, with the stand-in
CLI beside them, and runs `ReviewDialogsJourneyUITests` (one test, two launches of the app, 71 s).

The app is the real one in its real window: the photos arrive through the same URL admission a drop uses
(`-APUITestInputImages`, DEBUG only), and the test presses Start (`ap.ocr.start`). The reader is the Local Agent
backend pointed at `scripts/fake_local_agent.py`, a stand-in `claude` CLI that answers the app's prompts with
`fake_gateway.py`'s replies. It proposes the same thing for every photo, New Document and upright, so every
difference in the output is the test's hand. Apple Vision cannot read in the guest (W40.d1), and with no LLM it
could not open these dialogs anyway: Start refuses Automatic and Manual tagging with transcription-only Vision.

The output lands in the UI-test runner's own temporary folder, which the app can write and the runner can read.
The test opens every PDF with PDFKit (two pages, page 2's header, page 1's drawn photo) and decodes every Finder tag
xattr as a binary-plist array (`SPEC/tag-format.md`).

## Defects

1. **The per-page review's keys do nothing** (`W40.fix-processor-review-keys`, S3: the dialog works by mouse; fixed
   2026-11-20, the window takes focus on open and on a row click, and the journey now drives every key). README
   §Segmentation Review and the dialog's own header promise 1-4, X, ↑/↓ and Return. In both runs of 2026-11-19 none
   of them changed the review, and Return did not confirm it. `Views/OCRView+DocumentSegmentReviewSheet.swift` hangs
   its `onKeyPress` handlers on the content `VStack`, which has no focusable view, and its comment says the Confirm
   button's Return equivalent does not fire in the bare review window; the Segment & Tag canvas, which keys do reach,
   is `.focusable()` and focused on appear. The same handlers serve the Review rotation pass (←/→, [ ]), not driven
   by key here. Shots: `W40.d2-a-segmentation-keys.jpg` (after the keys), `W40.d2-a-segmentation-chosen.jpg`
   (after the clicks). The test records it as an expected failure naming the fix.
2. **Page 2's Classification keeps the proposal** (`W40.fix-processor-review-classification-stale`, S3, Tier-2: it
   writes output files). In both runs every page 2 reads `Classification: Document Start`, the stand-in's proposal,
   while the choices were Box, Folder and Continuation for photos 1, 2 and 4 and the Finder tags say so.
   `showFullSegmentationReview` writes the answer to the job and `updateClassification` rewrites the tags, but no
   step regenerates page 2 (the rotation pass does regenerate its PDFs). SPEC §2-page PDF structure makes the header's
   Classification the one consumers read, so a reviewed box reads as a document there. The test records it as an
   expected failure naming the fix.
3. **The Interrupted Run box names the wrong backend** (`W40.fix-processor-pending-run-caption`, S4). After a run
   killed mid-review (this journey's first attempt), the box read "6/6 files completed via Gemini Gemini 3.8 Flash",
   the stored provider, beside "Click Resume to continue with the Local Agent". `OCR/OCRProcessor+Pipeline.swift`
   builds the caption from `pending.provider` and `pending.model` whatever the backend. Shot:
   `W40.d2-pending-run-caption.jpg`. The journey now presses Dismiss when the box is there, as a user would.
