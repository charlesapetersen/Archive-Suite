## S-024 · The key wizard says Validated when the Keychain refused the key: reproduced

(1) `ProviderKeyWizard.validate()` still ignores `KeychainHelper.save`'s result and sets `keyValidated_<account>`. The
key row's chip shows "Save failed" only when the field has a key and `keySaveFailed_` is set, and only the manual edit
path sets that flag. Otherwise "Validated" wins (`Views/SettingsPanels/SettingsAccountsPanel.swift`, `keyChip`). After
`.apiKeyChanged` the row reloads its field from the Keychain (`reloadKeys`).

(2) Headless mode makes `save` refuse every write, as a locked or denying Keychain does. The wizard's step for a
passed check, then the row as it reloads:

```
account=Gemini  save_returned=false  field_after_reload=empty  keyValidated=true  chip=validated
account=OpenAI  save_returned=false  field_after_reload=empty  keyValidated=true  chip=validated
```

Settings shows a green "Validated" over an empty "Not set — paste a key" field. The SwiftUI button press itself was not
driven: the driver calls the function the button's task calls, after a usable result.

(3) Nothing calls it deliberate: `save`'s own comment says callers should surface a failure instead of showing "Saved".

## S-025 · "Fill in OpenAI preset" sets up a request OpenAI's reasoning models refuse: reproduced up to the wire

so the preset's `first(where: !supportsThinking)` falls back to the first entry, now GPT-5.4 mini (it was GPT-5 nano when
raised). The gateway reader is `OpenAICompatibleClient.gateway`, which sends `max_tokens`. Only the direct `.openai`
provider switches to `max_completion_tokens` (`OCR/OpenAICompatibleClient.swift:314-326`). The preset's own comment says

(2) The preset's fields, one photo, the request kept as the app built it:

```

```

OpenAI's answer was not observed: there is no OpenAI key on this Mac, and the Stanford gateway is not OpenAI's API. The
400 rests on the app's own statement (the preset's comment, `ArchiveProcessor/CLAUDE.md` §OpenAI-compatible gateway).
A live check costs under a cent with an OpenAI key.

(3) The preset's comment says it means to pick a model the gateway request works with, so the reasoning model it now
picks is not intended. No owner question.

## S-029 · A failed LLM rotation vote falls back to Vision without a word: half reproduced

(1) Still the case for the two LLM modes: a failed comparative call falls through to local Vision
(`OCR/OCRProcessor+OCR.swift`, `detectRotation`, `.llmSingle, .llmMajority`) with no unsure mark and no count. Two things
have changed since it was raised. The default mode, agreement, marks a page unsure when its cloud call fails, and the
summary counts those pages. The help no longer calls Vision about 60% accurate: it is now measured wrong on 3 of 119
held-out pages. README now says the app uses the Mac's detector "if the LLM check fails"
(`ArchiveProcessor/README.md:66`).

(2) A page of printed lines turned 90, 180 and 270 degrees. LLM comparative (one vote) on the gateway, every vote
answered 500:

```
── s029-llmSingle  Done. 3 succeeded, 0 failed. 2 box or folder labels read through the gateway (GPT 5.6 Luna), $0.0000.
   stand-in: 3 rotation votes, all 500 · page: turned-90 → 270, turned-180 → 180, turned-270 → 90 · unsure: none
── s029-agreement  (the default, same pages)  no rotation vote sent (Vision and PP-LCNet agreed) · same turns · unsure: none
```

All three votes failed, and nothing in the run says so: no page is marked unsure, and the status line does not mention
rotation. Vision turned all three synthetic pages correctly, so no sideways page came out. By the suspect's own
clearing line ("or the pages come out upright") the harm did not reproduce on this input. It matters for the pages the
help sends to LLM comparative, charters and non-Latin scripts, which it says the local models leave.

(3) README documents the fallback. It does not document the silence, and the default mode reports its own fallback,
so reporting the LLM modes' fallback would change nothing the documents promise. No owner question. A fix would keep
the fallback and count the pages.
