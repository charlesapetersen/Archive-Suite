# W40.d4 — one tiny real batch job per batch provider

- **Date and build:** 2026-11-18, Debug, at the commit that adds this file (parent `4c0bf811`).
- **Images:** the first three photos of the W40.c1 rehearsal copy of RG 165 — War Department
  (`verification/rehearsal.md`): `00001` a box label, `00002` a folder label, `00003` a document start.
- **Spend:** about $0.06 of real money by the app's batch estimates: Mistral $0.0060 a run (run twice, below),
  Anthropic $0.0479, and the cancelled Anthropic batch nothing billable (all three requests canceled before any
  succeeded). Within the $7 rule.
- Nothing ran on the host's screen. The runs' output is kept in `~/Library/Caches/ArchiveSuiteRehearsal/W40.d4/`.

## How it ran

`cd ArchiveProcessor && ./scripts/journey-bulk-ocr.sh --route anthropic|mistral --batch [--cancel] --paid --max 3`:
the W40.d1 journey (`BulkOCRJourneyUITests` → `ProcessFilesTestDriver` → `OCRProcessor.startProcessing`) with
`batchMode: true`, so the run takes `performBatchOCR`: the recovery journal, the provider's batch client's submit,
`pollBatchUntilComplete` and the result collection. The driver records the batch IDs from the journal once the
submission is marked complete (`batch.tsv`). With `--cancel` it presses Stop at that moment: the real
`OCRProcessor.cancel()` with the run held in `processingTask`, as `OCRView` holds it. Afterwards the script asks the
provider, with the same key, what became of each ID (`batch-status.txt`). The checker
(`scripts/journey_bulk_ocr_check.py`) ran `qpdf --check` and `pdfcpu validate` on every PDF, read page 2 against
SPEC/tag-format.md and decoded the tag xattrs.

## Anthropic: Stop after submission cancels server-side

```
batch.tsv     ids=msgbatch_01RE9DgX5PeZ2MBN8JmsNUYP submitted_after_s=2
              cancel=pressed journal_kept=false status=Cancelled. 0 succeeded, 0 failed, 3 skipped.
provider      {"processing_status": "ended", "request_counts": {"succeeded": 0, "canceled": 3}}
checker       RESULT: FAIL (3 failures) — expected: a cancelled run writes no PDFs
```

The provider confirmed the cancellation, so the app deleted the recovery journal (`journal_kept=false`), which is
the promised outcome for a confirmed cancel (`performServerBatchCancellation`). No Resume banner is left for a job
that no longer exists. One observation, not filed: the status line counts the three photos as skipped while the
job list marks them failed (`cancel()` composes the message before it marks the still-processing jobs failed); it
is the same for any Stop, not batch-specific.
