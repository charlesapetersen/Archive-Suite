# Archive Processor: triage of 630 more functions no run executed (views and the rest)

Paths are relative to `ArchiveProcessor/macOS/Sources/ArchiveProcessor/`. The per-function table is `W40.e4-never-reached-views.tsv` beside this file (630 rows; columns `file line function class group tested-by`).
Method (measured by search, not by running): for each non-trivial function, `rg -nw -t swift <base name>` over `ArchiveProcessor/macOS/Sources` and `packages/`, then over `ArchiveProcessor/macOS/Tests`; callers in `*TestDriver.swift` were counted as tests. SwiftUI closures and sheet triggers were followed by hand (`Views/OCRView.swift:600-700` lists every sheet and its trigger). "tested-by" comes from matching each file's accessibility identifiers and visible labels against `ArchiveProcessorUITests`, plus reading the tests that open the view. For rows inside a big view (OCRView, LiveCaptureView, the Settings tabs) the tester is assigned at the level of the view or the action the test clicks; it is a judgement from reading the tests, not a trace. The other 390 non-view functions are in `W40.e4-never-reached.md` and are not repeated.

## Most notable findings

1. **The review dialogs that write tags and move files are reached only by gated journeys (about 64 rows).** `DocumentSegmentReviewSheet` (Views/OCRView.swift:654), `BoxFolderConfirmSheet` (:657), `CollectionReviewSheet` (:617) and `CollectionFinalizeSheet` (Views/LiveCaptureView.swift:160) appear only in `ReviewDialogsJourneyUITests` and `LiveCaptureJourneyUITests`, which skip unless `PROCESSOR_JOURNEY=reviews` or `livecapture` is set. A plain UI-test run reaches none of them and no key-free driver does either. Ledger rows P-32, P-39, P-40.
2. **The per-document manual tagging sheet has no UI test at all (9 rows).** `ManualTaggingSheet` and `ManualTagSegmentView` (Views/ManualTaggingSheet.swift:17-247) open from `performManualTaggingPhase` (OCR/OCRProcessor+Tagging.swift:620, called at OCR/OCRProcessor+PostOCRFinalizer.swift:101) when a window segmenter or Live Capture cut the run. Only `DateRouteTestDriver` calls that entry, with no sheet on screen. The journey tests drive the other screen, Segment & Tag (`ManualSegmentTagView`).
3. **Typing subjects in a tag card is never driven (about 25 rows).** `SegmentTagCard` (Views/LiveCaptureView.swift:1237-1308), `ManualSegTagCard` (Views/ManualSegmentTagView.swift:452-501), `KeyboardTokenField` and `TagInputField` handle Return, Tab, Escape and delete for subjects. The one UI test that opens a card (`testManualSegmentCardTypesOneDateWithSentWithBelow`) types dates only. Subjects are what the controlled vocabulary and Finder tags are built from (P-36, P-38).
4. **Tools: three cards have no UI test.** Compare Models' results sheet and word diff (`OCRView+ModelTestResultsSheet.swift`, `OCRView+WordDiff.swift`, 10 rows), Test Resolution (`OCRView+ResolutionTestSheet.swift`, `OCRView+ResolutionDropSheet.swift`, 6 rows; the card is disabled without a key) and Processing History (`Views/ProcessingHistoryView.swift`, 8 rows). The ledger has no row for Processing History (its own drift list says so, verification/processor.md:1285).
5. **A dead enum case and an unpressed shortcut.** `ItemAction.fileAsImageOnly` (Views/Shared/ProcessableItem.swift:57) is never produced: no `availableActions` list includes it, and both handlers ignore it (Views/LiveCaptureView.swift:201, Views/OCRView.swift:1560), so "File as image-only" can never be shown. It is unused code, not a wrong behaviour, and it sits inside the `label` and `systemImage` rows listed as untested. Cmd-Option-P (Cycle Provider, `ProviderCycler.advance`, Views/ProcessingCommands.swift:64) has no tester.
6. **Everything that needs an account or a download is undriven.** ChatGPT sign-in (Views/ChatGPTPlanControls.swift:94), Google Drive sign-in and out (Views/Settings/SettingsCaptureTab.swift:102,124), key Validate and Test OCR (Views/ProviderKeyWizard.swift:219,236), Local Agent detect and verify, and the newspaper and hand-placer download rows (9 rows).
7. **Whole drivers never ran (61 rows, class dead = test-only).** `OpenRouterTestDriver` (25 rows; `scripts/test-openrouter.sh`), `ProcessFilesTestDriver` (12; `scripts/test-tier2.sh`, `scripts/live-openrouter.sh`), `LiveCaptureTaggingFailureTestDriver` and `NewspaperLayoutTestDriver` (4 each), `LabelGemmaVerifyTestDriver`, `HandLayerMeasureTestDriver` and `LocalAgentTestDriver` (3 each), `FileRelayTestDriver` and `OutputMeasureTestDriver` (2 each), and one closure each in `LiveCaptureTestDriver`, `LocalModelsTestDriver` and `TextLayerTestDriver`. They start from environment variables (`OPENROUTER_TEST`, `PROCESSFILES_TESTMODE`, `FILERELAY_TESTMODE`, `LOCALAGENT_TEST`, `APER_PLAN_DUMP`, `LIVECAPTURE_TAGGING_FAILURE_TEST`), so a missing run is a choice of what to run, not dead code. Where a driver ran and only a closure inside it did not (LocalAgent, LocalModels, TextLayer), the closure is a branch the run did not take.
8. **Real drag and drop is not exercised.** `DropReceiverView` (Views/DropReceiver.swift:27-40, 4 rows) is reached only by a real drag. UI tests feed files through a seam (`handleDroppedURLs`), and the ledger (verification/processor.md:519) records one manual Finder drop in S-048.

No suspected bugs: nothing found while reading had enough evidence to claim one.

How to read "tested-by": names are `Class.method`. `[gated: ...]` means the test skips unless that environment variable or flag file is present. `-` means no UI test drives it. A UI test "shown only" means the view appears on screen in it but the row's own action is not driven.
