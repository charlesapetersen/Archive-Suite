# S-053 · The label reader requests a model its gateway does not serve

2026-11-21 · Debug build at `85f7a7a8` · Codex gpt-6.2-sol · $0. Claude Opus 5.5
first captured the label request on the OpenAI preset in the [S-025 run](W49.proc-suspects-messages.md#s-025--fill-in-openai-preset-sets-up-a-request-openais-reasoning-models-refuse-reproduced-up-to-the-wire)
(`08f85025`). The new scratch run checks what a model-specific refusal does to the
label proposals and the run summary, with the S-052 counting fix already in the build.

## Reproduce

Build the Archive Processor Debug scheme with `ArchiveProcessor/macOS/build/DD`
as DerivedData. From the suite root, run outside the Codex sandbox.

```sh
python3 ops/autonomous/heavy-run.py run -- bash ArchiveProcessor/scripts/repro-s052-label-failures.sh missing-model
```

The existing headless Process Files driver uses the OpenAI preset model and endpoint
and calls `OCRProcessor.startProcessing`. The harness uses an isolated app copy and
two synthetic photos, a box marked “Box 17” and a blank folder label. It probes the
stand-in's model list before starting the app. The driver records each intended request
before redirecting it to loopback. The stand-in answers the preset's page transcription requests
and rejects requests for models outside its catalog with HTTP 404 and
`error.code: model_not_found`. No live provider or real key is used.

In `ContainerLabelCapture.readLabel`, every non-local gateway uses the fixed Luna
model ID. The label call retains status for charging and uses any returned text for
proposals. The model-unavailable reason never reaches the run summary. The S-052
fix counts both attempts as failures. The stand-in isolates this from S-025, which
concerns the page reader's request parameters against live OpenAI.

W49.proc-fix-s053 tracks carrying the unavailable-model reason into the summary.
Keep the Vision proposals and the S-052 success, failure and charge behavior. Reuse
the scratch run to check the new summary and preserve the working Luna route.

## Fix regression

The `missing-model` case now checks that the summary includes this sentence exactly once:

> The configured gateway reported that GPT 5.6 Luna was unavailable for box and folder label reading.

The same run must still save both PDFs, keep Vision's Box 17, warn about the empty folder
marker, and report zero gateway label reads and two failed attempts. The default HTTP 500
case checks that ordinary failures retain their counts without this diagnosis. The `mixed`
case makes Luna available in the stand-in's catalog and checks that its collection title
is saved alongside Box 17. It still reports one usable gateway read, one failed attempt,
and $0.0016 in simulated charges.

The diagnosis comes from the gateway's structured `model_not_found` response. A gateway
that returns another error keeps the ordinary failed-attempt count. The app makes the
same requests as before, with no additional catalog lookup.
