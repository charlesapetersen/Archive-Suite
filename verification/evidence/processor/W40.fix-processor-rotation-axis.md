# W40.fix-processor-rotation-axis — local Vision orientation

2026-10-31, Apple Silicon macOS, Debug production sources. Baseline detector: `2b760a21`
(unchanged at the starting `7564c188`). No paid recognition used for these measurements.

The old detector irrevocably chose an axis from four fast passes. One accurate pass already reads
all four orientations; its character geometry supplies the axis and flip together. The replacement
votes by first-to-last character direction in pixel coordinates, weighted by confidence × string
length. At least 80% must agree; unavailable geometry and single-character strings give no vote.
This leaves ambiguous pages to the existing OCR-result rotation fallback. `VisionQueue` still runs
the blocking recognition off Swift's cooperative pool with at most four requests in flight.

## Paired orientation measurement

All 96 frozen upright originals, excluding the three agreement-only pages (`p086`, `p094`, `p096`)
and including `p100`, physically rotated clockwise 0/90/180/270. Both detectors received the same
CoreGraphics-generated JPEGs and downscaled to a 1000-pixel long edge, under the shared heavy lock.
All 99 cached originals have EXIF orientation 1. Expected correction is `(360 - turn) % 360`.

| Detector | Exact / 384 | Wrong axis | Wrong flip | Abstained | Harness elapsed |
|---|---:|---:|---:|---:|---:|
| Baseline: fast axis + accurate flip | 342 (89.1%) | 29 | 0 | 13 | 174.85 s |
| One accurate pass, dominant character direction | 380 (99.0%) | 0 | 0 | 4 | 66.33 s |

The four remaining abstentions are p034 in every turn. Its accurate geometry has competing axes:
40 weighted characters horizontal versus 100 vertical on the unturned copy. A raw vector sum would
confidently pick the wrong axis; the dominance rule abstains. Changing the decoding scale to 1600
or minimum text height from .015 to .005 does not resolve that conflict. The reported p066 short-number
table and p090 dense type both now return the exact correction in all four turns, as does p042.

The recovered preliminary harness covered 98 pages rather than this exact 96: it included the
agreement-only pages and omitted p100. Its results were used only to diagnose the candidate; the
numbers above come from the corrected full-panel driver. Timing includes image generation and I/O,
not just recognition. This is a fixed development-set regression measurement; the policy was chosen
with these pages visible to the measurement, and the four turns of one page are correlated. It is
not held-out population accuracy, an OCR transcription score, or an end-to-end score of the fallback.

## Reproduction

From the worktree, outside the Codex sandbox (Vision), with `ARCHIVE_UNATTENDED=1`:

```sh
bash ArchiveProcessor/scripts/test-rotation-axis.sh
bash ArchiveProcessor/scripts/test-rotation-axis.sh "$HOME/Library/Caches/ArchiveSuiteRehearsal/ocr-panel-cloud/images"
bash ArchiveProcessor/scripts/test-rotation-deadlock.sh
```

Both scripts enter the shared heavy lock. The optional panel mode measures and prints every outcome;
it does not assert a target accuracy. `ROTATION_DETECTOR_SRC=/absolute/path/RotationDetector.swift`
selects a baseline or mutation source. Export the baseline with `git show
2b760a21:ArchiveProcessor/macOS/Sources/ArchiveProcessor/OCR/RotationDetector.swift`.
The harness uses only its own temporary output directory and reads panel inputs without modification.
