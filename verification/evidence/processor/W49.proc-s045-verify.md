# S-045 · Live Capture tagging refusal

2026-11-21 · Archive Suite baseline `7252c39b` · Codex `gpt-6.2-sol` · $0.

`ArchiveProcessor/scripts/repro-live-tagging-failure.sh` launches the Debug Processor headlessly with disposable backup and output directories. It arms the real Live Capture session through the existing recovery seam, then uses page receipt, End segment, Skip on the Mac tag card, and Finish with collection naming. Both documents have synthetic JPEGs and OCR text, and both receive a phone-entered date. The injected gateway returns subjects for the control and HTTP 500 for the second document. Sidecars are off and the phone date keeps the separate dating request out of this check.

The probe reads the staged and filed Finder tags and verifies that both filed PDFs retain the fixture OCR text. It records the same `SegmentItem` data and Finish warning predicate used by the Live Capture pane.

`LiveCaptureProcessor.computeTags` calls `TagGenerator.generateTags`, which keeps the fallback tags from `generateTagsReporting` and discards its failure reason. The successful Finder tag write therefore leaves the file-write warning clear, and the row has no OCR error to show. The owner’s filing rule allows filing complete PDFs after a tag-write failure, with a warning. The silence after a failed tagging request has no documented exception.

The headless run drove receipt directly and inspected row and summary data. Backup, PDFs and collection files stayed on scratch paths. The real Finish path can send synthetic originals and staging to Finder Trash. No bench cache was used.
