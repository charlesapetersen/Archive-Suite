# W40.fix-processor-a11y-secondary — evidence (2026-10-28)

Fix, two parts.

1. **The Processor's informational text is primary.** Every `Text` in its views drawn in `.secondary` (163 found
   by a script that walks back from each `.foregroundStyle(.secondary)` to the view it modifies, plus 12 by hand:
   `Label`s, text containers, the Live Capture "No phone connected" line, the segmentation badge) is now
   `.primary`. Where a ternary picked `.secondary` for the unselected state (`… ? .orange : .secondary`,
   `… ? Color.accentColor : .secondary`) only that arm changed, so the selected highlight stays. Kept `.secondary`:
   SF Symbols, status dots, strokes and fills (WCAG's 3:1 non-text floor), and the tag chip's remove button. Same
   rule as Notes (`W40.fix-notes-a11y-contrast`) and the Reader. No `Text` in the Processor's sources is
   `.secondary` any more. Light `.secondary` on white was 3.95:1; primary measures 14.13–14.94:1.
2. **The audit's large-text rule reads the letters, not the frame.** `AccessibilityAudit` (shared by all three
   UI-test bundles) gave 3:1 to any element with a frame 24 pt or taller, so a two-line caption passed as large
   text. It now measures the tallest run of pixel rows with ink under the frame (`ScreenPixels.inkHeight`: one
   line's letters, ascender to descender, ~0.95 em in SF) and treats 17 pt or more as WCAG large (18 pt). Each
   measured finding prints its letter height.

Runs (VM, `ONLY_TESTING=<App>UITests/AccessibilityAuditUITests ops/gui/vm-gui-runner.sh <app> xcuitest`), light
and dark each, 0 unexpected issues:

| App | Result | Letter heights seen |
|---|---|---|
| Processor (twice) | passed | "No saved profiles yet…" (26 pt frame, two lines) 10 pt — small text now, 14.13:1; "or use Add Files…" 8 pt; "Google client ID" 10 pt |
| Notes | passed | 2–15 pt (sidebar folder names 12–15 pt) |
| Reader | passed | none at 17 pt or more |

No screen in any of the three audits has text at 17 pt or more under a contrast finding, so the rule change moved
no verdict on these screens; what it closes is the two-line-caption loophole the frame rule left.
