## Functional proof with external tools denied

A scratch `sandbox-exec` profile applied to the app and its children:

```scheme
(version 1)
(allow default)
(deny file-read* (subpath "/opt/homebrew") (subpath "/usr/local") (subpath "/opt/local"))
```

The control `/bin/cat /opt/homebrew/Cellar/qpdf/12.3.2/bin/qpdf` failed with Operation not permitted
under that profile. Both copied Release tools answered their version options under it with an empty
environment and `PATH=/usr/bin:/bin`. No installed tool was renamed, chmodded, or otherwise changed.

Release deliberately has no test drivers. A scratch copy of the freshly built Debug app received the
exact signed Release `jbig2`, `qpdf`, `lib/`, and `third-party-licences/`; the enclosing scratch app was
re-signed with the suite identity, preserving its flags/entitlements, and passed deep strict verification.
The production PDF writer was measured through `scripts/measure-output.sh`, using its new
`OUTPUT_MEASURE_APP=<scratch-app>` and `OUTPUT_MEASURE_PROFILE=<profile>` overrides. The Python launch
boundary unblocked TERM/INT to avoid the separately queued inherited-signal-mask harness issue.

With external tools denied, **ALL PASS**: generated memo, every output form, selectable reading words,
one-page searchable form, XMP header read-back, Finder tags, merged page order and headers. Searchable
output was **21,677 bytes**, compression **4.3 s**, with `/JBIG2Decode` present. All six PDFs passed
veraPDF PDF/A-2b validation. The bundled qpdf's `--check` passed on the searchable output under the same
profile. Its Poppler-rendered 1200-pixel PNG was inspected: all six memo lines draw clearly, without
clipping or blank content.

The negative control used the same app/profile, additionally denying reads of its two bundled helper
paths. It failed exactly the compression assertion with `jbig2 and qpdf not found`, wrote **127,698
bytes** with no `/JBIG2Decode`, and retained all other measurement checks/PDF-A validations. This proves
the positive result did not silently use an installed external tool. Each headless app child exited
normally when the measurement script sent TERM.

Real packaging failure paths were also exercised: running the Release phase with Homebrew denied
returned 1 for `jbig2: not installed`; `CODE_SIGNING_ALLOWED=NO` returned 1 before copying tools.

## Review and limits

A separate read-only adversarial review found no blocking defect in build-phase placement, strict
failure propagation, relocated dependency validation, inside-out signing, or measurement overrides.
No production PDF/output code or package source changed; this is packaging of the existing route.

The Homebrew tools here are **arm64-only**. The Processor app remains universal, and Runner ignores
incompatible bundled tools: Intel still needs native installed tools. This matches Vision OCR's existing
bundling behavior and is documented in Processor's known issues and release reference.

text and accurate/fast Vision reads of EXIF orientations 1, 3, 6 and 8. The

rerun is claimed for this packaging-only change.
