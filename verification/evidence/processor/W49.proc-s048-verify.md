## Source and independent check

`OCRView.selectFiles` and the populated list's `DropReceiver` both reach `OCRView.admit`,
then `OCRView.add` appends the collected URLs. `OCRView.beginProcessing` sends that list to
`OCRProcessor.startProcessing`, where each occurrence gets a job. `IncrementalSkip.partition`
checks the input list against existing PDFs at the start of the run. It also deliberately treats
repeated base names as ambiguous for that purpose. Neither check collapses repeated input URLs.
`OCRProcessor.uniqueOutputURL` reuses the output path recorded for the same source URL, so
counting files in the destination alone can miss duplicate reads.

For W49.proc-s048-check, a separate Claude session should verify both repeated-add paths and the
loopback request counts in a fresh scratch run. Check one single-add control and verify that
the same pathname is used for each pair. Record the model and result before filing a fix.

## Fix (W49.proc-fix-s048)

2026-11-24 · Debug in the macOS 27.2 Tart VM · Claude Opus 5.5 · $0.

`OCRView.add` now passes each intake through `ProcessFilesTree.withoutRepeats`, which leaves out a file the list
(or an earlier file of the same intake) already names. Two URLs are one file when they share a device and inode
(`ProcessFilesTree.fileIdentity`), so `/var` and `/private/var`, a linked folder, a hard link or another letter case
all count; the resolved path is the fallback for an unreadable file. The Files list then says "Already listed, not
added again: <name>." (`ap.files.repeatNote`). `OCRProcessor.startProcessing` also refuses a list that repeats a
file (`ProcessFilesTree.firstRepeat`) before any recovery state or request, for Live Capture and the test seams.

The regression `NamesEstimateJourneyUITests.testRepeatedAddListsThePhotoOnce` replaces the check's case and runs
the same route (`PROCESSOR_JOURNEY=namesestimate ops/gui/vm-gui-runner.sh processor xcuitest`). The Open panel
cannot select a linked file itself, so the other-name case adds the photo through a linked folder (the runner's
temporary folder is in its container, which has no `/private` alias).
