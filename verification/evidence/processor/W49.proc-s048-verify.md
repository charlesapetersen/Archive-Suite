## Source and independent check

`OCRView.selectFiles` and the populated list's `DropReceiver` both reach `OCRView.admit`,
then `OCRView.add` appends the collected URLs. `OCRView.beginProcessing` sends that list to
`OCRProcessor.startProcessing`, where each occurrence gets a job. `IncrementalSkip.partition`
checks the input list against existing PDFs at the start of the run. It also deliberately treats
repeated base names as ambiguous for that purpose. Neither check collapses repeated input URLs.
`OCRProcessor.uniqueOutputURL` reuses the output path recorded for the same source URL, so
counting files in the destination alone can miss duplicate reads.

For W49.proc-s048-check, a separate Claude session should verify both repeated-add paths and the
loopback request counts in a fresh scratch run. Check one single-add control and verify that
the same pathname is used for each pair. Record the model and result before filing a fix.
